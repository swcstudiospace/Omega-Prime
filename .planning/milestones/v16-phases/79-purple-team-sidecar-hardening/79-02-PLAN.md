## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| case-file→runner | Case YAML is data but author-controlled; malformed or hostile YAML must not execute |
| gateway-seam→verdict | Observed detection strings are untrusted input to the pass/fail decision |
| findings-store→export | NDJSON store is append-only; export must not mutate history |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-79-07 | Tampering | sidecar/cases/*.yaml | high | mitigate | Schema validation on every load; version bump required on edit; payloads inert strings, never eval/exec |
| T-79-08 | Spoofing | detection events | high | mitigate | Pass requires exact expected_detection match per case_id; mismatch implies FAIL naming the case, never a pass |
| T-79-09 | Repudiation | findings rows | medium | mitigate | Append-only NDJSON with ts; dedupe increments occurrence_count instead of rewriting history |
| T-79-10 | Tampering | version drift | high | mitigate | VERSION + tool-surface compared against contract on every run; mismatch implies DEGRADED with pair named |
| T-79-11 | Information disclosure | payloads in reports | low | mitigate | Reports record normalized response digests and verdicts; raw payload text stays in the versioned case file |
| T-79-12 | Denial | residual_rationale abuse | medium | mitigate | Rationale excuses exactly its own case_id; suite still requires 100% everywhere else |
</threat_model>
