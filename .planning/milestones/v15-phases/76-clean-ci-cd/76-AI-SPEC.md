## 1. System Classification

**System Type:** Code Automation — maintenance and local conformance validation only; no new AI runtime

**Description:**
Preserve the existing Omega Prime custom Python/pytest/structural-eval/MCP SDK validation stack. Phase76 adds CI-retained isolated readiness evidence and reproducible hardened artifact validation/manual publication controls. Good means supported gates remain blocking, complete sanitized evidence is retained, and any optional publication is explicitly gated to the same validated bytes and source commit. Sources: `76-CONTEXT.md`, REQUIREMENTS CI-01..03, `75-VERIFICATION.md`; selection: `agent://Native76FrameworkSelection`.

**Critical Failure Modes:**
1. Required scenario, roster-accounting or CI-gate failures must not become successful receipts.

4. Structural/model-double/local-host proof must not be described as live Grok/provider/backend proof.

## 1b. Domain Context

**Industry Vertical:** Developer tooling — repository CI/CD maintenance and local readiness evidence for the existing Omega Prime programming agent and Grok MCP tool host; not a new AI capability.

**User Population:** Repository maintainers and contributors deciding whether a change is safe to merge; Grok tool-host operators interpreting local conformance evidence, build artifacts and future manual publication/rollback instructions.

### What Domain Experts Evaluate Against

**Dimension: Supported merge gates remain meaningful**
- **Good (domain expert would accept):** Python3.12–3.14 verification, lint and type jobs retain their observed receipts; eval/assembly/catalog/docs checks and independent pinned native/license/parity gates remain required where applicable. The committed-lock audit retains only its documented PYSEC-2026-4114 exception. Permission, concurrency and timeout cleanup removes genuine redundancy without converting a failed, skipped or unobserved stage into a passing execution.
- **Bad (domain expert would flag):** A supported interpreter or independent gate disappears; an audit exception expands; a green workflow summary is presented as proof that a skipped check ran.
- **Stakes:** High
- **Source:** [CI-01 and locked controls](76-CONTEXT.md#locked-boundary); inspected baselines: [CI](../../../.github/workflows/ci.yml), [lockfile audit](../../../.github/workflows/supply-chain.yml), [native/parity/license jobs](../../../.github/workflows/rust-parity.yml), [exception rationale](../../../SECURITY.md#dependency-exceptions). [GitHub permission guidance](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions) supports minimum explicit token access; workflow text does not prove remotely configured required checks.

**Dimension: Failure evidence is usable without exposing credentials**
- **Good (domain expert would accept):** The maintained isolated readiness CLI produces retained sanitized success and failure evidence beside the existing receipts, with the real outcome, failed scenarios and named prerequisites preserved. Rejected or unavailable diagnostics are identified safely as unavailable, not replaced by raw logs or a fabricated successful report. Parent credentials and user state are not treated as disposable fixtures.
- **Bad (domain expert would flag):** Only successful reports survive; a retention step masks readiness failure; bearer tokens or raw rejected stderr/host diagnostics enter logs, summaries or uploaded artifacts; a missing report is called a pass.
- **Stakes:** Critical
- **Source:** [CI-02](../../REQUIREMENTS.md#cicd), [LOCAL-01 and LOCAL-02](../../REQUIREMENTS.md#local-integration), [locked evidence boundary](76-CONTEXT.md#locked-boundary), [security reporting and secrets posture](../../../SECURITY.md), [token-file handling](../../../docs/deploy.md#the-token-file). These are acceptance criteria, not a claim that the baseline image workflow already sanitizes every failure-log path.

**Dimension: Tool effects and proof boundaries are honest**
- **Good (domain expert would accept):** Every roster tool has an actually exercised, feature-disabled or named-prerequisite-blocked outcome. Local production dispatch is accepted only with checked effects in owned disposable paths; both MCP transports, authentication, approvals and shutdown have their own evidence. Scripted/model-double/local-host results are labelled local conformance, not live Grok quality, external backend durability or account attachment.
- **Bad (domain expert would flag):** Tool discovery or a non-error return is counted as execution; a default-profile result is stretched to cover an unavailable optional profile; a loopback host verifier or scripted workflow is advertised as live provider/service proof.
- **Stakes:** High
- **Source:** [LOCAL-01..03, FLOW-01..02 and GROK-01..02](../../REQUIREMENTS.md), [live-proof exclusions](../../REQUIREMENTS.md#out-of-scope), [host authentication scope](../../../SECURITY.md#remote-tool-host), [deployment evidence limitations](../../../docs/deploy.md#what-was-verified). The baseline workflow's “live host” step means an owned container host, not a live Grok model.

**Dimension: Future publication uses the artifact that was validated**
- **Good (domain expert would accept):** Image validation retains read-only uid10001 operation, capability dropping/no-new-privileges, both transports, graceful SIGTERM, SBOM and the blocking critical scan. Optional publication stays default-off and manual, rejects an unprotected ref or source-commit mismatch, and uses the validated bytes rather than rebuilding them. Rollback guidance identifies the previously validated artifact/digest and makes clear that this milestone publishes and deploys nothing.
- **Bad (domain expert would flag):** A manual trigger alone is treated as sufficient authorization; validation from a different commit is reused; an unverified rebuild is published; SBOM presence is called a clean scan; deployment-check promotion warnings are treated as enforcement of approval.
- **Stakes:** Critical
- **Source:** [CI-03](../../REQUIREMENTS.md#cicd), [locked publication controls](76-CONTEXT.md#locked-boundary), [image validation baseline](../../../.github/workflows/grokbot-image.yml), [same-digest promotion and warning-only findings](../../../docs/deploy.md#staging-first-then-gated-promotion), [GitHub manual-trigger semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onworkflow_dispatch), [protected-branch controls and bypass caveats](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches). These are required Phase76 controls, not evidence that optional publication or remote protection is already configured.

**Dimension: Synthesized knowledge-base updates stay reviewable**
- **Good (domain expert would accept):** CI refresh remains PR-only, visibly skips when its secret is missing, and never auto-merges synthesized content. Future human review distinguishes the historical synthesized mirror from current source-verified documentation; incomplete retrieval must fail visibly and retain the last complete mirror when the Phase77 KB requirements are implemented.
- **Bad (domain expert would flag):** A missing-secret skip is called a completed refresh; generated KB text is merged automatically or treated as canonical source evidence; Phase76 claims that PR creation proves complete retrieval or human review.
- **Stakes:** High
- **Source:** [locked KB boundary](76-CONTEXT.md#locked-boundary), [refresh workflow and review notice](../../../.github/workflows/kb-refresh.yml), [KB-01..03 and Phase77 mapping](../../REQUIREMENTS.md#greptile-knowledge-base). ### Known Failure Modes in This Domain

These are source-backed failure conditions to evaluate, not a claim that production incidents were observed:

1. **False-green maintenance:** matrix/gate removal, skipped stages or discovery-only accounting make a receipt look complete while required execution/effects remain unobserved. Sources: CI-01, LOCAL-02..03 and the inspected CI/native baselines.
2. **Unsafe failure retention:** diagnostic fallback exposes tokens or discards failed evidence; the baseline image workflow has raw `docker logs` failure paths, so an existing workflow must not be presumed to meet Phase76's sanitized-evidence contract. Sources: [image workflow](../../../.github/workflows/grokbot-image.yml), CI-02 and SECURITY.md.
3. **Release identity or authority drift:** a different commit, unprotected ref or rebuild breaks the link to validated bytes; warning-only promotion checks are mistaken for blocking authorization. Sources: locked context and [deployment promotion guidance](../../../docs/deploy.md#staging-first-then-gated-promotion).
4. **Overstated operational assurance:** local/model-double or skipped-prerequisite results become live-provider claims; a missing-secret KB skip or generated PR is misrepresented as a complete, human-reviewed refresh. Sources: GROK-02, milestone exclusions, KB-01..03 and the refresh workflow.

### Common Pitfalls

1. **Treating the detector as a universal secret oracle.** `secret_guard.py` combines audit patterns, PEM/`omk_` patterns and a heuristic for mixed-class token-shaped strings of at least32 characters; hex/UUID/low-diversity candidates are deliberately excluded. A clean scan cannot prove arbitrary text is secret-free. Prevent inherited secrets, redact known minted tokens, and gate complete diagnostics before clipping; do not widen or weaken the detector to manufacture a pass.
2. **Passing `os.environ.copy()` into local validation.** `build_child_env` intentionally constructs owned paths and interpreter/locale values without reading the parent environment. Reintroducing provider keys, proxies, HOME or inherited TMPDIR defeats isolation. The receipt helper's inherited CI stdio/environment is a separate boundary, not permission to inherit it in the product child.
3. **Calling scripted/stubbed results live model proof.** `runner.py` uses `ScriptedModel`, canned tools and a hermetic ultrathink runner. Readiness also explicitly labels its model-double seams. They prove local machinery/composition only, even when real persistence and dispatch are exercised.
4. **Equating wiring or `ok` with consumer effects.** Tool discovery, registration, a non-error dispatch, or manifest agreement does not prove correct output. Existing loopback checks assert returned bytes and the file in owned work; warm intake checks use an independent persisted producer and the already-warm consumer. Preserve those assertions and failed negatives, not source/workflow-text tests repinned to implementation spelling.
5. **Losing failure semantics during publication/transport cleanup.** Gate full details and metadata before clipping, publish fixed safe labels on rejection, and retain non-success. Do not upload raw child stderr/host logs as a fallback. `verify.py` can have `skip` checks while `ok` remains true, and readiness can be `ok` with named blocked/disabled tools: neither means everything ran. Preserve real SDK sessions, timeouts and cleanup; a sync wrapper inside an event loop is not an async API.

**Model Configuration:**
No live model call, model selection, provider configuration or prompt change is required or authorized by Phase76. Existing xAI/Grok integration remains unchanged and uncalled by local validation. **Tool Use:**
No new model tools, framework dependencies, tracing services or installs. Keep production registry/host dispatch, canonical roster and existing targeted local approvals. These approvals authorize disposable local effects, not external-service grants. The current SDK boundary uses `Client(transport, mode="legacy")`, `sse_client` on `/sse`, and `streamable_http_client` on `/mcp` with `httpx2.AsyncClient(trust_env=False)` for HTTP; session entry performs initialization. Await the current client's `list_tools`/`call_tool`, preserving manifest comparisons, refusal checks and timeouts. The verifier consumes an already-running owned host; readiness owns its loopback host. A call-token-only verifier can skip admin approval roundtrips, so retain skip/prerequisite evidence and the separate readiness deny/grant/revoke effects.

Keep image validation read-only at uid10001, capability-drop/no-new-privileges and owned temporary state, both transports, graceful SIGTERM, SBOM and the blocking critical scan. Optional publication configuration stays default-off, manual, protected-ref/same-source-commit gated and uses validated bytes, not a rebuild; this milestone executes neither publication nor deployment. Preserve independent security/native/license gates and all supported matrices (CI-01..03), without importing a deployment or tracing platform into this contract.

**State Management:**
Reuse `isolated_layout`: safe exported install plus separate HOME/work/state/audit paths, explicitly constructed child environment, fresh fixture values, and cleanup on all exits. Parent controller owns only the explicitly requested report write outside that layout. Preserve exact-byte artifact checks and real store reopening/warm-consumer assertions. `sys_cache` is in-memory and approval state is not durable; do not promote either to persistence proof. Readiness's temporary journals and local model-double state are not production memory or cross-process backend proof.

**Context Window Strategy:**
There is no inference context window, RAG retrieval or agent compaction change in this phase. Keep complete structured scenario outcomes, roster accounting, limitations and receipts as evidence; human display clipping is a publication-format concern only. Known-secret redaction and the unchanged secret gate must see full diagnostics before flattening/clipping, and final serialized reports must pass the publication gate. Never summarize away failed checks, named prerequisites or proof limitations to fit an artifact or log.

## 4b. AI Systems Best Practices

These practices apply to the existing Code validation stack, not to a new inference service.

### Structured Outputs with Pydantic

The product already validates readiness reports with stdlib `validate_report` and exactly-once canonical roster checks; `VerifyReport` uses dataclasses. Keep those implementations and wire formats. The following **instructional consumer example is not a mandatory product rewrite**, new dependency, new report format or proof that current production uses these models. It validates the actual aggregate shape returned by `run_suite`, including count/result consistency, using Pydantic2 already present in the resolved stack (lockfile2.13.5; not claimed pinned in fresh-resolve CI).

```python
from typing import Self

from pydantic import BaseModel, ConfigDict, Field, ValidationError, model_validator

from omega_prime.grokbot.secret_guard import SecretLeakError, assert_no_secrets


class CaseEvidence(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")

    id: str = Field(min_length=1)
    passed: bool
    failures: list[str]

    @model_validator(mode="after")
    def consistent_result(self) -> Self:
        if self.passed != (not self.failures):
            raise ValueError("case outcome and failure list disagree")
        return self


class StructuralEvidence(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")

    passed: int = Field(ge=0)
    failed: int = Field(ge=0)
    results: list[CaseEvidence] = Field(min_length=1)

    @model_validator(mode="after")
    def consistent_counts(self) -> Self:
        passed = sum(case.passed for case in self.results)
        if self.passed != passed or self.failed != len(self.results) - passed:
            raise ValueError("aggregate counts and case outcomes disagree")
        return self


def validate_structural_evidence(text: str) -> StructuralEvidence:
    try:
        # Complete serialized run_suite output, not a clipped excerpt.
        # Pydantic types/validators are not a secret detector.
        assert_no_secrets(text, "structural-evidence")
        evidence = StructuralEvidence.model_validate_json(text)
    except (SecretLeakError, ValidationError):
        # ValidationError can contain input bytes; do not print/chain it.
        raise ValueError("structural evidence rejected") from None
    return evidence  # evidence.failed > 0 remains an actual failed evaluation
```

Instructional input is the complete `json.dumps(run_suite(...))` result, not the runner CLI's human `PASS`/`FAIL` text. A schema-valid failure is retained as failure; a typed object proves shape/invariants, not actual execution, coverage or live-model quality. Keep canonical roster reconciliation in `validate_report`/`account_roster`; this eval example does not replace it or invent roster coverage.

**Retry/surfacing policy:** zero automatic schema/model retries for deterministic CI evidence. Surface malformed/secret-rejected evidence immediately as non-success; retain only a fixed safe classification and observed command/exit identity, never raw exception text or input. Independent eval cases/scenario modules still aggregate their own failures. An authorized later rerun is a distinct observed run, not a retry-until-green loop. There is no LLM output to repair with `response_format`, `instructor` or a judge.

### Async-First Design

For an existing event loop, `await arun_verification(...)`; for a synchronous CLI, the existing `run_verification` wrapper owns its single `asyncio.run`. Calling that sync wrapper inside a running loop raises rather than making the work asynchronous. MCP transports are async context-managed `Client` sessions; await complete tool results and retain existing timeout/failure checks and `aclose` cleanup. SSE is a transport here, not permission to stream unvalidated evidence.

Keep the synchronous stdlib readiness controller/process isolation instead of converting it to an async orchestrator. Its fresh child owns a process group; timeout kills the group (including its loopback host) before layout cleanup. Loopback normal shutdown sends SIGTERM, waits and only escalates if necessary. Preserve these lifetimes and bounded CI jobs. Publish only completed, validated, sanitized reports—not partial child stdout, raw stderr or raw host logs. There is no model-token UX stream in Phase76.
