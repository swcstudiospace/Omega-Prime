# Phase 77.1 Plan 01: Generated /omega-<name> command tracer Summary

**Multi-segment whole-message `/omega-<name>` parser plus a pure deterministic generator that adds 34 skill/routine commands behind the 12 curated ones, dispatched through the existing `omega_command` tool with a locked fail-loud collision rule.**

## Performance

- **Tasks:** 2
- **Commits:** 1 (`50b621a`; plan window `eebbe2c` → `50b621a`)
- **Files modified:** 5 (2 created, 3 modified)

## Accomplishments

- `_COMMAND_RE` accepts multi-segment names while keeping whole-message matching, case-folding and args capture. Curated names, behaviour and order are unchanged.
- New `omega_prime/commands/generated.py` builds the generated entries without importing `omega_prime.commands`. It reads skills sorted by folder and routines sorted by stem, using git-tracked files when `.git` exists and the files on disk otherwise. It produces exactly `/omega-python-skill`, `/omega-onboard-routine`, `/omega-connectors-routine`, `/omega-ultrathink-skill` and `/omega-ultrathink-routine` as the suffixed names.
- Generated dispatch:
  - A skill command returns `{kind, source, description, instructions, args}`.
  - A routine whose exact stem is in `WORKFLOW_NAMES` runs the existing `_workflow` path, with approval gating. `desk-lead` never maps to `desk`.
  - Any other routine returns its full text.
  - A missing source returns `ok:false` with `source_missing`.
- `/omega-help` and both `unknown_command` lists cover all 46 names.
- Wave-0 `test_command_generation.py` (34 tests) was added, and the pinned parser and surface suites were extended.

## Decisions Made

- `CommandSpec` lives in `generated.py`; `omega_prime.commands` still exports it. This was the only way to return specs without the forbidden import of `omega_prime.commands`.
- `checked_in_skills` / `checked_in_routines` only enumerate: they never raise and return `()` when the folders are absent. This is the contract agreed with the 77.1-04 writer.

## Deviations from Plan

Writer-reported (`Write77101`):

1. **`CommandSpec` moved to `generated.py`.** It is the same single dataclass with two defaulted fields (`kind="curated"`, `source=""`), re-exported from `omega_prime.commands`.
2. **One spec parser input is not asserted `None`: `"/omega-help\n/omega-doctor"`.** It parses as `/omega-help` with args `/omega-doctor`, both today and with the prescribed regex. Rejecting it would change curated parsing, which the same spec row forbids. Every other malformed or prose input is asserted `None`.
3. **Additional error codes the plan does not name.** `catalog_generation_failed` is returned by `/omega-help` (with the curated list and the reason) and by any non-curated name after generation aborts. `source_unreadable` and `source_invalid` are returned when a skill file exists but cannot be read or has no frontmatter.
4. **Tests patch a private attribute.** The `source_missing` and conflict tests point `omega_prime.commands._CATALOG_ROOT` at a tmp tree, so no real files are deleted.

**Impact on plan:** No scope creep. The tests needed 77.1-02's lead-pack frontmatter to generate all 27 skills; both landed in wave 1 before the gate run.
