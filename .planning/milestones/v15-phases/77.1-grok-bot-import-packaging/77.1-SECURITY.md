## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| User message → command dispatch | Whole-message `/omega-<name>` text. Only names that pass the regex reach the catalog | untrusted chat text |
| Catalog key → filesystem | Skill and routine files are read by catalog key only, never by args | repo-tracked file paths |
| Skill frontmatter → platform loader | `name` and `description` go to Cursor and Grok Bot YAML parsing | checked-in metadata |
| Tool description → model | `omega_command` `_DESCRIPTION` goes into the Bot prompt | static text |
| Bot computer shell → network/FS | pip, git and venv run with the user's privilege | lock-pinned packages |
| Bootstrap output → stdio stream | Every bootstrap byte must stay off stdout until the final exec | MCP JSON-RPC framing |
| Token file/env → SSE host | Bearer material reaches the host by argument only | **secret** |
| Template lists → generator and lint | Skill and routine names are checked against files on disk | names |
| Manifest text → operator and Bot | Capability and transport claims | claims |
| Rendered text → committed files and Bot computers | mcp.json, `.cursor-plugin/*`, the HTTPS example and 46 command files | must hold no secret |
| Generator output → CI and setup gates | Drift verdicts that gate merges | pass/fail |
| Docs → operator and Bot | Setup commands, placeholder syntax, evidence levels | credential guidance |
| Declared command → test harness / local proof → seal | The exact mcp.json argv, and owned-process evidence | proof claims |

### Non-blocking notes (no disposition change)

- **N-01 (T-12 hardening, low):** `HEADER_PLACEHOLDER_RE` (`plugin.py:89`) accepts any `${UPPERCASE_VAR}` of any length. A hand-edited example such as `Bearer ${AKIA...}` (uppercase/digit-only) would be sentinel-masked in a standalone `secret_problems` call. It is still caught: render always emits `HTTPS_TOKEN_VAR`, and the drift byte comparison (`plugin.py:589`) fails the edited file as stale in `--check`, setup_check, CI and bootstrap. Optional fix (not applied): require the placeholder to be exactly `Bearer ${OMEGA_PRIME_MCP_TOKEN}` (or its `env:` form), i.e. compare with `HTTPS_TOKEN_VAR`.
- **N-02 (T-16 verification wording):** the plan's "secret-gate-clean docs text" check cannot pass literally. The unchanged detector flags prose such as "bearer host", and pre-phase docs tripped it too. No automated docs secret scan exists. The control rests on review of each hit (done above), and no credential values were found.
- **N-03 (T-09 test depth):** no adverse test forces a lock-acquisition failure. Fail-closed behavior was confirmed by reading `grokbot-1click.sh:245-253`.
- **N-04 (T-08):** `rm`, `mv`, `flock`, `readlink` and `dirname` run without an explicit `</dev/null`. They do not read stdin, and fd 1 already points at stderr.
- **N-05 (ownership model):** ownership is stamp-based by design (`grokbot-1click.sh:20-22`). If an operator hand-replaces `.venv` next to an existing stamp, the bootstrap treats it as owned and rebuilds it. `build_venv` also removes leftover `.venv.old.[0-9]*` siblings (`:204-207`).
