# Phase 77.1 Plan 03: Idempotent locked launcher bootstrap Summary

**`grokbot-1click.sh` now resolves its root from its own location and gains `--bootstrap` / `--bootstrap-only` / `--verify`. Bootstrap is flock-serialized, stamp-gated and lock-only, keeps stdout protocol-only, and fails with distinct exit classes 10-13. `oneclick.py` closes the carried Phase 75 findings WR-01, WR-02 and IN-01.**

## Accomplishments

**Launcher (`omega_prime/scripts/grokbot-1click.sh`)**
- **Root and streams:** the cwd-first root walk is gone; a portable symlink loop is the only way the root is found. `exec 3>&1 1>&2` sends all bootstrap output to stderr. `GIT_TERMINAL_PROMPT=0`, `PIP_NO_INPUT=1` and `PIP_DISABLE_PIP_VERSION_CHECK=1` are set.
- **Prerequisites:** bash, git, python3 ≥ 3.11 with venv/ensurepip, flock, `pyproject.toml` and `requirements-lock.txt`. Anything missing → exit 10.
- **Submodules:** `prime-agent` is initialized only when `ROOT/.git` exists; otherwise a warning goes to stderr. `redteam` appears nowhere.
- **Lock and stamp:** an exclusive flock on `ROOT/.venv.lock` never fails open. The 0600 stamp sidecar `ROOT/.venv.omega-prime-bootstrap.json` covers the lock and pyproject hashes, the interpreter and the prime-agent commit. A warm start runs only the import probe.
- **Cold build:** the build happens in `ROOT/.venv.build`:
  1. create the venv;
  2. `pip install -r requirements-lock.txt`;
  3. `pip install --no-deps -e ROOT`;
  4. import probe;
  5. atomic rename into place;
  6. second import probe;
  7. write the stamp last.

  Any failure → exit 11, with no stamp and the previous venv untouched.
- **Drift and verify:** a non-zero `plugin --check` → exit 12. Verify mode delegates to `python -m omega_prime.tooling.plugin --root ROOT --verify [--json]` (owned by 77.1-05), and any non-zero exit → 13.
- **Final exec:** fd 1 is restored only for the final `oneclick --root ROOT --transport stdio --skip-doctor ARGS`.

**oneclick (`omega_prime/grokbot/oneclick.py`)**
- WR-01: the stdio argv carries `--work-root` after `--audit-log` when it is set. The help text says the flag reaches both the stdio and the SSE host.
- WR-02: `_exported_token` and its `with` block are deleted. The token reaches `serve_sse` only through its argument.
- IN-01: `run_preflight_doctor` is deleted. `_run_preflight`, the served-stdio stderr routing and the module-load imports are unchanged.

**Tests**
- New Wave-0 `test_grokbot_bootstrap.py` (27 tests) uses a private PATH with stub `python3`/`git`/venv python. The stubs write noise to stdout and drain stdin, so a missing fd swap or `</dev/null` fails a test.
- `test_grokbot_oneclick.py` flips `env_seen` to `[None]` and adds `test_stdio_launch_forwards_work_root`.

## Deviations from Plan

Writer-reported (`Write77103`):

1. **Stamp location.** The stamp is the sidecar `ROOT/.venv.omega-prime-bootstrap.json`, as named in the plan artifacts and PATTERNS A-M5, not a file inside the venv. It has one extra field, `python_executable`.
2. **Shebang fixup.** After the build-then-rename, a small Python fixup rewrites the venv's `bin/` shebangs and `activate*` scripts from `.venv.build` to `.venv`. Without it, console scripts would point at the deleted build directory.
3. **Corrupt-venv rebuild.** A stamped venv that fails the warm import probe is rebuilt instead of exiting 11, so a corrupted venv resumes safely.
4. **Extra prerequisites.** The prerequisite list also reports `flock`, `python3-venv` (Python is new enough but venv/ensurepip is missing), and missing `pyproject.toml` / `requirements-lock.txt`.
5. **Strict mode arguments.** `--bootstrap-only` takes no other arguments, and `--verify` accepts only `--json`. Anything else exits 2, so a usage mistake is never reported as host_unreachable.
6. **No-flag path.** With no mode flag the old behaviour stays: pick the best Python, no bootstrap. It now passes `--root ROOT` explicitly and no longer walks up from the cwd.
7. **State defaults scope.** `OMEGA_PRIME_STATE_DIR` / `OMEGA_PRIME_WORK_ROOT` defaults are exported only in bootstrap modes and only when unset.
8. **Recorded risk (superseded).** In a developer checkout, `--bootstrap` with an existing unstamped `.venv` replaced it with a lock-only venv, following the AS-05 placement at `ROOT/.venv`. Correction `0b3d182` removed this risk; see Post-verification corrections.

**Impact on plan:** All deviations serve the stated idempotency, stream and failure-class contract. No scope creep.
