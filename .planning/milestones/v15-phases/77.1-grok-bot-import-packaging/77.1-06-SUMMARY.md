## Deviations from Plan

Writer-reported (`Write77106`):

1. **PyYAML as a floor.** The dependency is `>=6.0.3`, not `==6.0.3`. Every other runtime dependency in pyproject is a floor, and `requirements-lock.txt` says CI installs from pyproject floors to catch fresh-resolve drift. The floor is the locked version, so no new package or version is introduced.
2. **Default deselection through `addopts`.** The plan's acceptance says the opt-in cold test is skipped by default and runs only on explicit selection, and registering a marker does not do that by itself. `addopts = "-m 'not slow_bootstrap'"` provides it, and a later command-line `-m slow_bootstrap` overrides it. No test uses the marker yet, so `pytest -m slow_bootstrap` currently selects nothing and exits 5. The slow case is owned by 77.1-08.
3. **The generator's own VCS lookup.** The row is in-process, but `plugin.render` → `checked_in_skills` → `tracked_paths` runs `git ls-files` when `root/.git` exists. That is the generator's own lookup, not a shell-out to the plugin CLI or the launcher. For that reason the no-spawn test uses a tmp tree without `.git`.
4. **Unreceipted CI step.** The new step is a plain `run:` in the unreceipted `docs` job, mirroring the catalog step it sits beside. `STAGES` is unchanged.

**Impact on plan:** No scope creep. The plan's must_have that the docs gate list names the plugin check belongs to 77.1-07 (CONTRIBUTING/README gate lines), which this plan did not touch.
