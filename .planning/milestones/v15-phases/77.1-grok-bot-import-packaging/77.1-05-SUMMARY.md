# Phase 77.1 Plan 05: Deterministic plugin generator with check and verify Summary

**`python -m omega_prime.tooling.plugin` renders the whole import manifest set: the Cursor plugin and marketplace manifests, a stdio-only root `mcp.json`, 46 `/omega-<name>` command files and a non-secret HTTPS example. `--check` catches every drift, frontmatter, collision, template and secret class without writing, and `--verify` proved both entries against the real repository root.**

- **Commits:** 1 (`1dfd944`; plan window `0b3d182` → `1dfd944`)
- **Files created:** 52 (generator, tests and 50 generated files)

## Accomplishments

- **CLI:** `--root R` with exactly one of `--check`, `--write` or `--verify [--json]`; `--json` only with `--verify`. It mirrors `tooling.catalog`: the success line goes to stdout, problems go to stderr as `plugin --check: <path> ...` with exit 1, and a generation error prints `generation failed; nothing written`.
- **Render:** `render(root)` returns a path-sorted mapping with stable key order and trailing newlines, and collects every problem before raising `PluginError`.
  - `plugin.json` takes version, description, repository/homepage, author, license and keywords from `pyproject.toml` via `tomllib`.
  - `mcp.json` args come from `manifest.STDIO_COMMAND`: `bash ${CURSOR_PLUGIN_ROOT}/omega_prime/scripts/grokbot-1click.sh --bootstrap --transport stdio`.
  - Commands come from `COMMANDS` plus `generate_commands`. Empty skills or routines abort naming the directory, and the declared launcher must exist.
- **Checks:** skill and command-file frontmatter conformance (PyYAML imported in the check, failing closed when absent), two-way template lint through `manifest.lint_template`, and `assert_no_secrets(str)` on every rendered and committed text. The HTTPS example is shape-validated first (one server, url and headers only, `https://<host>/mcp`, `Authorization` exactly `Bearer ${VAR}`), then its header is replaced with a fixed sentinel before the unchanged gate runs.
- **Write:** `atomic_write_text(mode=0o644)` for changed files only. Only owned `omega-*.md` orphans are removed; any other file in the commands directory fails.
- **Verify:** both entries always run.
  - **stdio:** spawns exactly the declared command from a temp cwd in a new session. A raw JSON-RPC client sends `initialize`, `notifications/initialized` and `tools/call omega_command /omega-help`, rejects any non-JSON-RPC stdout line, and requires the listed names to equal the catalog.
  - **https:** validates the example statically, then runs `oneclick.run_self_test(root)` with `require_auth=True` over sse and http, with its report on stderr.
  - Exit 0 only when both resolve; otherwise exit 1 with `<entry> entry FAILED: ...` on stderr.
- **Tests:** Wave-0 `test_grokbot_plugin.py` covers the manifest schema, both entry shapes, the secret gate, frontmatter, the 46-entry catalog, determinism, the roster, 23 parametrized drift classes, failure-atomic writes, orphans, absent PyYAML and the verifier.

## Deviations from Plan

Writer-reported (`Write77105`):

1. **Provenance by kind.** Command files say "from the curated catalog", "a checked-in skill" or "a checked-in routine" instead of the source path. A path like `omega_prime/skills/code-review/SKILL` tripped the unchanged secret gate's bare-token heuristic on 16 files in the first `--write`, which failed closed and wrote nothing. The gate was not weakened; the second run wrote all 50 files.
2. **`--check` imports `manifest`.** It imports `omega_prime.grokbot.manifest` for `lint_template` and `STDIO_COMMAND`, which pulls in `mcp_server` (about 6-7 seconds of imports). The plan forbids reimplementing `lint_template`, so PATTERNS' wish to keep the render free of `mcp_server` cannot also hold.
3. **No `--out`.** `--write` is the regenerate mode; the plan allows either name.
4. **Path form.** `plugin.json` component paths use the RESEARCH R01 form without a leading `./`; the marketplace entry uses `"source": "./"` (AS-12).
5. **No `type` key in the HTTPS example.** It is url plus headers only, as in RESEARCH; Cursor infers the transport from `url`.
6. **Inherited environment.** In verify, the stdio child inherits the caller's environment, as a real Bot launch would; `mcp.json` itself carries no env.
7. **No on-disk mode pin.** No test pins the committed files' mode, because a checkout's mode follows the umask; the 0644 write is asserted in the tmp-tree write test.
8. **mypy correction (parent-requested).** `_project` narrows `project.get("urls")` to a dict or `{}`. A missing `[project.urls]` still surfaces as the existing missing-field `PluginError`.

**Impact on plan:** No scope creep. All deviations stay inside the plan's must_haves and prohibitions.
