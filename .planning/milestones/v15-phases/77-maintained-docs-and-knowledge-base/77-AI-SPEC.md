## 1. System Classification

**System Type:** Code — developer tooling and complete historical-document mirroring, not a new inference system.

**Description:** Source-verified canonical repository guidance plus one complete historical Greptile mirror with identity/version/count/fetch provenance and fail-closed refresh. Maintainers must distinguish actual local proof from optional/unexecuted provider/backend operations and synthesized material from authoritative source.

**Critical Failure Modes:**
1. Partial/truncated/mixed-version or wrong-repository retrieval presented as a complete mirror.
2. Failed refresh damages the previous complete set or unchanged content causes timestamp-only churn.
3. Synthesized historical content treated as instructions or current canonical implementation truth.
4. Documentation omits approved capabilities, invents live/approval claims, or presents unsafe/unrunnable setup.
5. Credential material, path escape or unknown publication state reaches saved/public output.

### What Domain Experts Evaluate Against

**Dimension: A complete, identifiable historical edition**

- **Good (domain expert would accept):** One `kb/` mirror contains all 21 exact listed paths, including `index.md`, with full returned bodies from repository `swcstudiospace/omes-bot`, namespace `3b0877f2-8580-4305-b246-a1cf4cfb31f3` and retained version `2026-10-08-1791571202911-c82b36`. The collector receipt reports 21 expected/retrieved/full documents and no truncation; actual local import remains a separate consumer proof.
- **Bad (domain expert would flag):** A default 20-item page, missing index, duplicate/renamed path, wrong namespace, mixed version, absent body or capped prefix is labelled complete; a manifest count substitutes for readable full files; missing retrieval time is invented. Search excerpts or summaries stand in for omitted bodies.
- **Stakes:** High.
- **Source:** KB-01; `77-CONTEXT.md`; primary listing/get-document schemas; retained snapshot and fetch receipt. The get-document cap covers the serialized response and offers no continuation parameter.

**Dimension: Keep the last good mirror and make substantive changes reviewable**

- **Good (domain expert would accept):** Refresh uses `namespaceId` and fails visibly on absent, malformed, partial, truncated, count-inconsistent or mixed-version input. Missing/empty publication is not complete21 success. A late fetch or publication/write failure leaves the prior complete documents and manifest intact. An unchanged accepted publication retains existing bytes and fetch provenance rather than changing timestamps; genuine path/version/body changes remain visible.
- **Bad (domain expert would flag):** A second-fetch error leaves a new index with old remaining files, or a failed write leaves a partially updated edition; single-file atomic replacement is claimed to protect the whole mirror. A weekly timestamp-only diff obscures real content changes, or failure is described as a successful empty refresh.
- **Stakes:** Critical.
- **Source:** KB-02 and locked no-churn decision; `omega_prime/tooling/fs.py::atomic_write_text/atomic_write_json` provide file-level, not set-level, replacement. Parent receipt `local://v15-phase77-refresh-preservation-before.json` records an actual legacy second-fetch failure changing `index.md` and failing previous-complete-byte preservation; this is known baseline failure, not a retested or repaired result.

**Dimension: History stays evidence, never operating authority**

- **Good (domain expert would accept):** The synthesized historical edition remains visibly untrusted and separately navigable from current canonical docs. Readers can identify its source/version and find current guidance. Embedded commands, URLs or role directives do not determine execution, organization scope, credentials or approval. Historical synthesis is not silently rewritten into current truth, and current documentation is not duplicated into the mirror.
- **Bad (domain expert would flag):** An old synthesized runtime/security claim is promoted into canonical instructions without source confirmation; an embedded directive is followed because the document was retrieved; historical content controls tool arguments or requests broader permissions. Fetch completeness is advertised as factual correctness or prompt-injection immunity.
- **Stakes:** Critical.
- **Source:** KB-03; snapshot classification and `77-PATTERNS.md` trust boundary; OWASP LLM01:2025 recommends segregating external content and code-enforced privilege boundaries. Greshake et al. demonstrate indirect injection through retrieved data, including code-completion systems; this supports a downstream risk, not a claim that this importer performs inference or has suffered that attack.

- **Stakes:** Critical.

### Known Failure Modes in This Domain

1. **Incomplete edition published as complete:** Listing defaults hide the 21st path; a full-source character count accompanies a truncated prefix; a publication changes between calls. A plausible index or manifest does not reveal the missing/mixed body to readers.
2. **Refresh destroys the recovery copy or generates review noise:** The reproduced legacy late-fetch failure changes the index before all documents are available. Set-level write failure has the same preservation concern; unconditional fetch stamps bury substantive changes in routine PR churn.
3. **Historical guidance launders instructions or obsolete architecture:** Synthesized text can contain stale toolchains/security assumptions or adversarial directives. Users or downstream assistants may act on it when the historical/current boundary disappears. This is a known external attack class and an identified deployment risk, not an observed attack here.
4. **Inventory and local preparation become false operational claims:** A generated catalog, source-symbol count, setup command or local model-double receipt is described as successful external capability use. Newcomers then omit optional toolchains/services, mishandle host credentials/approvals, or assume live Grok, publication/deployment or protected approvals occurred.

### Specific Pitfalls

1. **Copying the old namespace parameter.** Both the inspected importer and the offline Greptile tools guide use `repoNamespaceExternalId`; current mounted requests require `namespaceId`. Change discovery plus list/get callsites and their consumers together; do not retain a fallback alias.
2. **Treating a page as the publication.** Default limit 20 is smaller than the retained 21-document set. Validate integer counts (not booleans/coerced strings), `returned == len(documentPaths)`, unique paths, progress and stable totals/identity/version across pages. An empty page, scan cap or duplicate cannot silently complete a snapshot.
3. **Confusing schema-valid strings with complete source.** Baseline `document.get("content", "")` accepts absent content, and a capped prefix can look like valid Markdown. Require declared content and full counts, reject truncation, and compare each document's path/repository/namespace/section/version to its listing.
4. **Equating atomic files with an atomic mirror.** Baseline writes each document before the next fetch and then writes a manifest. A late failure leaves a partial new set. Fetch and validate everything before touching the published mirror, and provide set-level failure preservation in addition to the existing atomic helpers.
5. **Publishing diagnostics or timestamps as evidence.** Baseline tool errors clip remote text to 200 characters before safety classification and `_stamped` always inserts a fresh timestamp. Whole-input secret gating must precede any clip/echo; an unchanged validated set must retain existing bytes, including original fetch provenance.

These pitfalls are grounded in source and primary schemas; no unfetched GitHub issue is asserted as evidence.

### Model and Supporting Integration Configuration

**No model is selected or invoked.** Temperature, output-token parameters, provider retries, prompt caching and model-judge settings are inapplicable to this deterministic Code maintenance task. Existing Grok/provider product behavior is unchanged. No RAG/vector/embedding integration, new telemetry or live-quality judge is authorized. ### Core Pattern: Observe Completely, Validate, Then Publish

Current request construction, shown without credentials, calls or writes:

```python
namespace_id = "3b0877f2-8580-4305-b246-a1cf4cfb31f3"

# These are current mounted API argument shapes, not a new product API.
listing_request = (
    "list_knowledge_base_documents",
    {"namespaceId": namespace_id, "limit": 100, "offset": 0},
)
index_request = (
    "get_knowledge_base_document",
    {"namespaceId": namespace_id, "path": "index.md"},
)
# The existing client uses client.call_tool(tool_name, arguments).
# Subsequent get paths must come from the complete validated listing.
# Do not publish from these individual observations.
```

**Approved implementation design, not already-implemented behavior:**

1. Resolve the repo through existing discovery using canonical `namespaceId`; reject ambiguous/malformed/truncated discovery. Retrieve the entire listing, checking page shape, progress, unique safe paths, counts, namespace/repository, section version and index presence. For the retained import, require exactly the snapshot's 21 listed paths and retained version, not merely any 21 files.
2. Collect `index.md` first and then every remaining listed document without writing the published mirror. Verify each identity, section/version, declared full character count and absence of truncation. Treat full bodies as literal untrusted archival data; never execute them or derive credentials, tenancy or commands from them. Missing content is an error; never manufacture an empty document. The unchanged Grok diagnostic scanner applies to full error/diagnostic input before clipping or echo, not to archival bodies.
3. Re-list the complete publication after fetching. Compare namespace/repository, unique path set, total, index state and section version map to the before-listing; all fetched documents must match those versions. A changed publication invalidates the entire candidate. The endpoint reads current publication only: the retained historical snapshot is a supplied complete artifact, not a version-addressable live fetch.
4. Assemble complete document bytes plus provenance and validate the entire candidate before publication. Preserve the exact primary bodies and exclude client credentials, session headers and environment values from mirror provenance. Do not redact a historical body and call it exact. The parent exercised all 21 captured bodies through the diagnostic scanner: its bearer-header pattern rejects the ordinary descriptive phrase “bearer credentials” in `docs/prime-kernel-and-substrate.md:87`. Applying that diagnostic-only scanner to an entire source archive was an extra inferred restriction, not the requested KB contract. Keep the scanner unchanged and its full-input diagnostic boundary enforced; see `local://v15-phase77-corpus-boundary-decision.json`.
5. Compare candidate source identity/path/version/content/count/completeness to the previous complete manifest and file bodies, ignoring the new observation time for equality. If all substantive data matches, return an honestly unchanged outcome and leave every byte/timestamp-bearing header/manifest untouched. Keep original fetch provenance; do not turn a no-op observation into a PR.
6. Only for substantive change, stage the whole validated set in owned private storage using `ensure_private_dir`, `atomic_write_text` and `atomic_write_json`. Publish docs and manifest as one recoverable operation; if publication can fail between replacements, retain enough prior owned files/manifest to restore the **entire** prior complete mirror before surfacing failure. A manifest written last is not by itself rollback. Keep the maintained `kb/README.md` and unrelated files outside generated-file removal. Clean owned transient staging on all exits. Never delete the prior set merely because upstream is empty or a refresh fails.

## 4b. AI Systems Best Practices

### 4b.1 Structured Outputs with Pydantic

Here the structured output is an **untrusted MCP document observation**, not an LLM answer. Pydantic is already recorded in current dependencies (`requirements-lock.txt`: 2.13.5); the importer presently uses dictionaries. The following local instructional fixture uses real Pydantic v2 APIs, adds no dependency/client rewrite and performs no network or writes. It illustrates one-document shape/semantic rejection, **not** full21 or set-publication acceptance. Production diagnostic handling is separate from literal archival content.

```python
from pathlib import PurePosixPath
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, ValidationError


NAMESPACE = "3b0877f2-8580-4305-b246-a1cf4cfb31f3"
REPOSITORY = "swcstudiospace/omes-bot"
VERSION = "2026-10-08-1791571202911-c82b36"


class DocumentObservation(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid", frozen=True)

    namespaceId: str = Field(min_length=1)
    # Existing response metadata only; never send it as a request argument.
    repoNamespaceExternalId: str | None = None
    repoName: str = Field(min_length=1)
    path: str = Field(min_length=1)
    section: Literal["docs"]
    versionId: str = Field(min_length=1)
    characterCount: int = Field(ge=0)
    content: str = Field(min_length=1)  # Required: no absent-content default.


class DocumentEnvelope(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid", frozen=True)

    document: DocumentObservation
    untrustedContent: bool
    notice: str = Field(min_length=1)
    truncated: bool = False
    truncationReason: str | None = None


def validate_observation(raw: dict, expected_path: str) -> DocumentEnvelope:
    # Validate literal archival data; do not execute or echo rejected input.
    # Production gates full error/diagnostic text before any clipping.
    result = DocumentEnvelope.model_validate(raw)
    doc = result.document
    path = PurePosixPath(doc.path)
    if (
        result.untrustedContent is not True
        or result.truncated
        or result.truncationReason is not None
        or doc.namespaceId != NAMESPACE
        or doc.repoName != REPOSITORY
        or doc.versionId != VERSION
        or doc.path != expected_path
        or path.is_absolute()
        or ".." in path.parts
        or "\\" in doc.path
        or path.as_posix() != doc.path
        or not (
            doc.path == "index.md"
            or (doc.path.startswith("docs/") and doc.path.endswith(".md"))
        )
        # This ASCII fixture has identical codepoint/UTF-16 counts.
        or doc.characterCount != len(doc.content)
    ):
        raise ValueError("KB observation rejected")
    return result  # Remains untrusted; no publication authorization is returned.


# Authored minimal fixture, not copied historical content or live evidence.
fixture = {
    "document": {
        "namespaceId": NAMESPACE,
        "repoName": REPOSITORY,
        "path": "index.md",
        "section": "docs",
        "versionId": VERSION,
        "characterCount": 4,
        "content": "# X\n",
    },
    "untrustedContent": True,
    "notice": "Synthetic fixture; untrusted data, not instructions.",
}

try:
    observation = validate_observation(fixture, "index.md")
except (ValidationError, ValueError):
    # Never print the exception: schema errors may contain rejected input.
    raise SystemExit("KB observation rejected") from None
else:
    print("Local fixture shape accepted; no snapshot published")
```

Strict fields prevent coercion of strings/bools into evidence counts; required content prevents silent empty-document substitution. Extra-field rejection is this small fixture's intentionally closed schema, not a promise that all future server extensions are invalid. Production parsing must explicitly handle known envelope/document metadata without ignoring truncation; path validation must additionally enforce resolved output-root containment, symlink safety and generated-path ownership. Parent exercised this instructional fixture: valid and literal archival-prose controls accepted, truncated/wrong-version/wrong-count/empty-body cases rejected; `local://v15-phase77-ai-boundary-example-proof.json`. This is not production-import proof.

**Validation/retry policy:** Zero automatic schema/model repair retries and zero provider-judge calls. A malformed observation aborts the candidate and preserves prior complete material. Record only a fixed failure category and trusted field/rule identifiers, never error input or remote text. Surface the failed refresh immediately; a separately authorized future refresh starts over with before/after metadata, rather than splicing an individual retried document into a failed candidate. No `instructor`, `response_format`, LLM repair loop or `.with_structured_output()` applies to this custom stack.
