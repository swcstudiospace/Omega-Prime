<objective>
Build the dashboard half of sbx-4 visibility (W113-01, W113-02): omega_prime/dashboard/herdr_launch.py — a never-raising pane launcher that opens one Herdr pane per sandbox run (herdr workspace create + pane run, pane id parsed from stdout, tmux-fallback returning "tmux:<session>") — and omega_prime/dashboard/run_rows.py — the tasks.json row lifecycle (start/touch/finish) written exclusively through locked_tasks + _write_locked with herdr_pane/last_activity_at/receipt additive fields and terminal rows never resurrected. </objective>

<assumption_delta_decision>
- Decision: keyword-only `session` on open_pane (deviation from the literal W113-01 signature, forced by the layer rule) — the fallback session name is an engine convention (omega-<job>, jobs.py:97) that the dashboard must not derive; passing it in keeps herdr_launch engine-free and directly testable. Default None disables the fallback (documented None path).
- Decision: the herdr/tmux children get a minimal env {PATH, HOME} built from the caller env, not child_env — the dashboard cannot import engine child_env, and a two-key env guarantees no credential-bearing values ride into pane processes or their receipts (T-113-01).
- Decision: start pins started_at at first creation and never resets it on a re-start (the row is one run's record; a crash-resume must not look brand new); herdr_pane is overwritten only when a real pane opened this time.
- Decision: finish upserts — a missing row is created terminal. A run whose start was suppressed (unwritable store then, writable now) still deserves its terminal record; the row lifecycle is the truth for run state, mirroring raise_block's "the item, not the row, is the source of truth" split.
- Decision: touch is a no-op (no write at all) for a missing or terminal row — late events after finish must neither resurrect nor churn the store; only the owning row's fields are ever assigned, so unknown fields on other rows survive byte-for-byte through the whole-store read-modify-write.
- No add-alongside debt: exactly three dashboard files, two new modules + exports, nothing else.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Engine (caller) → herdr/tmux child processes | The dashboard spawns foreign binaries (herdr, tmux) with a caller-supplied label and command; argv and env cross this edge. |
| run_rows → tasks.json store | Row writes cross into the file other dashboard writers (engine failure wiring, digest routine, push hooks) read and write under the same flock. |
| Responder → waiting_on_ove items | The additive fields this phase defines (herdr_pane, last_activity_at, receipt) are read by operators and, for `answer`, by 113-02's poll — nothing here writes items. |
