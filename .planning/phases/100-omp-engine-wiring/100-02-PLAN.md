## Summary

Replace the broken directory-as-filter wiring with one bounded implementation:
a run-owned project skills view at `<effective --cwd>/.omp/skills`, containing
additive per-skill links to real skill source directories, selected by omp's
own discovery with `--skills "*"` so user and non-omega-prefixed skills stay
selectable. Implement this design only if 100-00 confirms this exact
project-local mechanism and symlink behavior. Otherwise stop as BLOCKED and
replan; do not copy skills or try another configuration. Omega names derive
from the existing checked-in catalog. GSD names and roots come only from the
100-00 evidence record. The already-acquired workspace owner from 100-01 owns
MCP and skills artifacts together. Documentation and central full-gate
verification belong to 100-05.

Current broken state (planning-time evidence):

- `omega_prime/engine/mcp_bridge.py:11-17` — `skills_dir()` returns the
  checked-in `<install>/omega_prime/skills` and its docstring wrongly says omp
  loads it via `--skills`.
- `omega_prime/engine/omp_driver.py:366,386-387` — `_run()` passes that
  absolute directory as the `--skills` value; observed installed omp 18.12.3

- `omega_prime/engine/omp_driver.py:413,507` — session.json records the

## Design (one bounded implementation)

**Attach shape.** Before spawning omp, `_run()` builds the view:

1. Derive Omega names from the existing catalog:
   `checked_in_skills(install_root())` (`omega_prime/commands/generated.py:110-112`,
   falls back to a directory scan without VCS). This yields the 28 first-party
   names including `omega-commands` and non-omega-prefixed names such as
   `python`. No second roster is maintained; `omega_prime/redteam/pack/skills`
   is never scanned, so redteam names (`tempest-run`, `blue-sentinel`, ...)
   cannot leak in.
2. GSD names and roots come only from the 100-00 record. If G2 shows the
   root is already natively discovered, do not create duplicate view links;
   prove resolution of an actual GSD name with the real loader. Otherwise
   link each evidenced GSD skill directory as for Omega.
3. Validate that each source has a readable `SKILL.md`; do not add manifest
   mismatch skip rules beyond the installed loader's evidenced contract.
4. Reject collisions between intended Omega and GSD link names with an
   `attach_failed` status naming both paths. Resolve collisions with user or
   global roots according to the evidenced loader precedence.
5. Create `<work>/.omp/skills` under the existing workspace owner and create
   one symlink per skill to its absolute source directory. Record and publish
   each artifact through `register_artifact(relative_path, prepared_identity)`
   and the owner's nofollow, no-replace protocol; cleanup only registered
   artifacts in reverse order.

**Ownership matrix.**

| State of `<work>/.omp/skills` | Action |
| --- | --- |
| Absent | Create the view and links; register every artifact with the workspace owner |
| Stale run owner | Recover only registered run-owned artifacts per 100-01 |
| Real directory, not run-owned | Back off: `attach_failed`, reason `skills_view_preexisting`; zero writes |
| Symlink (user link) | Back off: `attach_failed`, reason `skills_view_is_symlink`; never resolve or write through it |
| Live workspace owner held by another job | Back off per 100-01 concurrency semantics |

Backoff never deletes or rewrites anything. `attach_failed` is recorded in
session.json and the session proceeds without the view.

**Filter.** Pass `--skills "*"` as the sole filter. The glob is verified by
100-00 to preserve all discovered skills, including user skills, actual GSD
skills, and non-omega-prefixed first-party names. No enumerated roster is
passed in argv.

**GSD runtime reporting.** Runtime discovery may report
`sources.gsd.status = "missing_prerequisite"` for an explicit error-behavior
test. Missing actual sources still blocks completion and cannot satisfy
acceptance.

**session.json.** Replace the `"skills"` string (omp_driver.py:413,507) with:

```json
"skills": {
  "filter": "*",
  "status": "attached | attach_failed",
  "view": "<path or empty>",
  "reason": "",
  "linked": [{"name": "...", "source": "..."}],
  "sources": {
    "omega": {"status": "attached", "root": "<install>/omega_prime/skills", "count": 28},
    "gsd": {"status": "attached | not_linked_native | missing_prerequisite", "root": "...", "names": []}
  }
}
```

Planning-time search found no reader of the `skills` key (tests read
`model`/`stage` only; `EngineResult` has no skills field). Re-verify
references at execution before changing the shape.

**Sandbox.** Use only the already-established sandbox binds. If an evidenced
GSD source root is not visible through those binds, stop BLOCKED and replan;
do not widen the sandbox or add forwarding configuration in this plan.

**No global effects.** No writes to `~/.omp`, no settings edits, no login
store access or copying, no `--profile`, no user skill directory mutation,
no new packages, and no time caps.
