# 100-01 — Project-local MCP attachment with ownership-aware cleanup (wave 2)

Future execution instructions for an authorized execution session. Nothing
here has been executed; APIs marked **new** are proposals the executor may
rename, while the must_haves invariants are binding. Full plan ID:
`100-01`.

## Design (parent-decided; bounded, no overbuild)

Reuse the existing bridge and persistence; add only the lease logic that is
missing. The current flow (`omega_prime/engine/omp_driver.py:331-513`) writes
`mcp.json` + `.mcp.json` into a per-job profile directory, launches omp with
process cwd = profile while passing `--cwd <work>`, and never checks that omp
loaded anything. This plan replaces that with:

1. **One attachment owner** in `omega_prime/engine/mcp_bridge.py`:
   - `mcp_server_entry(python, work_root) -> dict` (**new**) — the pure
     payload builder preserving today's no-secret stdio entry
     (`sys.executable -m omega_prime.mcp_server --root <install>
     --work-root <work>`; absolute interpreter, no `CURSOR_PLUGIN_ROOT`, no
     env values).
   - `try_acquire_attachment(work_root, state_root, job_id) ->
     AcquiredAttachment` (**new**) — no-follow, no-replace acquisition:
     durable private intent journal first (`<job_dir>/attachment.json`,
     workspace key, payload sha256, owner pid + `/proc/<pid>/stat` starttime
     ticks), fsyncing the journal and its parent directory; then create and
     fsync the exclusive workspace lease. Open the project and `.omp`
     directories with directory-relative no-follow handles; create `.omp`
     relative to its verified parent, fsync that parent, and durably journal
     its inode before continuing. Write the complete config to a private
     staging inode relative to the verified `.omp` descriptor; fsync the
     file, durably record its dev/ino and fingerprint in the journal, and
     fsync the journal and parent directory before atomic no-replace
     publication relative to that same descriptor. Fsync the `.omp`
     directory after publication. Never create the final config before its
     complete staged inode is durably journaled. Every crash boundary,
     including `.omp` mkdir before journal update, either has an identity-safe
     recovery action or preserves the uncertain directory/entry and fails
     closed. Path-based lstat followed by pathname open is insufficient.
   - `AcquiredAttachment.register_artifact(relative_path, prepared_identity)`
     (**new**) — validates a prepared artifact beneath the same workspace,
     records its identity durably on the existing owner journal without
     acquiring another lease, and makes it part of that owner's cleanup/
     recovery set. 100-02 uses this exact seam for skills; it must not
     independently acquire the workspace.
   - `AcquiredAttachment.release()` (**new**) — reverse-order, identity-
     checked cleanup using directory-descriptor-relative no-follow operations;
     remove an artifact only while its recorded parent and dev/ino/fingerprint
     still match. Journal cleanup transitions durably before destructive
     operations and fsync each affected parent after unlink. On any swap or
     mismatch preserve the uncertain entry and report conflict. Remove a
     run-created `.omp` only through the verified descriptor when the recorded
     directory is still owned and empty; durably complete the journal before
     removing the lease.
   - `recover_stale_lease(...)` (**new**, invoked inside
     `try_acquire_attachment`) — bounded next-safe-run recovery only: reclaim
     solely when recorded owner and child identities are proven dead and all
     surviving artifact/parent identities match the durable journal. Unknown
     or partial records, uncertain publication, live/unproven process, or
     any mismatch preserve lease and entries and back off.
2. **Driver lifecycle** in `_run`: keep one owner open through acquisition,
   spawn, session use, and proven child reaping. Parent death between `Popen`
   and child identity registration must be prevented by a durable
   spawn-registration handshake or leave a fail-closed journal state that
   cannot be reclaimed until child death is established. If close/kill/wait
   leaves a possibly-live child, do not release or clean artifacts; preserve
   journal and lease. Acquisition backoff never blocks the launch: the
   session proceeds to one `prompt` with status `attach_failed`.
3. **Discovery-based status**: after `set_thinking_level` and before
   `prompt`, `_attachment_status(session)` (**new**) issues the exact
   session-visible discovery command and matches Omega tools from the
   installed evidence. Require the effective configured server command
   established by 100-00, not merely familiar tool names. Status lands in
   `EngineResult.mcp_status` (**new** field, default `"attach_failed"`),
   `session.json`, and one host-side `mcp_attachment` event per run.
   `attach.py _engine_body` carries the field to routed consumers.
4. **Removal of obsolete paths**: `write_mcp_json` and both profile JSON
   writes go away; the `profile/` directory is no longer created; Popen cwd
   becomes the effective work root (matching `--cwd`). Check exported-symbol
   references with the language server before editing; use grep only for
   known textual leftovers such as `write_mcp_json` and `profile`.
