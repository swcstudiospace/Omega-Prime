Make ultrathink ship writes an explicit, fail-closed opt-in shared by every runtime consumer. One strict parser decides capability from an explicitly supplied environment mapping, the bridge enforces it ahead of root resolution and runner selection, MCP wiring and the eval runner inject that mapping from their existing explicit env sources, and focused tests prove the exact flag/approval crossproduct with fakes only. <context>
This is the wave-1 plan for WIRE-07-01 with no intra-phase dependencies. Today the bridge has approval gates but no shipping opt-in: UltrathinkContext carries only root/run/timeout (omega_prime/tools/ultrathink.py:56-62), _call resolves root first and then the runner (77-100), and no ULTRATHINK_SHIP parser exists anywhere in the tree. default_registry injects only ULTRATHINK_ROOT (omega_prime/mcp_server.py:980-983) after normalizing env with env = dict(env or {}); load_runtime is the sole ambient boundary, copying os.environ only when env is None (mcp_server.py:1391-1405, 1438-1445). The eval runner dispatches through the real registration with a fake runner and a context of root='eval-hermetic' plus run only (omega_prime/evals/runner.py:212-253).

Registry dispatch checks policy, then approval, then the handler (omega_prime/tools/registry.py), so a bridge-local gate in _call runs after approval succeeds and before any CLI call: an unapproved disabled ship tool still reports approval required; an approved disabled tool reports ship_disabled. Gate-before-root is intentional for valid arguments, which changes bare ship_pr from not_configured to ship_disabled; its named test is updated deliberately, not treated as a regression. Public state validation stays before _call.

The parser contract is exact strings only: ship_enabled(env) is true only when env.get('ULTRATHINK_SHIP') is '1' or 'true' — no strip(), lower(), case folding, bool(), or truthiness conversion; absent key, '', '0', 'false', 'FALSE', 'TRUE', 'True', ' true ', '1 ', 'yes', 'on', '2', and non-string values all mean off. The bridge must never consult os.environ: an explicit mapping without the key defeats an ambient ULTRATHINK_SHIP=1, and the default subprocess runner keeps its existing process-env inheritance only because the bridge gate already decided capability.

Scope guards: APPROVAL_TOOLS, ULT_TOOL_NAMES, schemas, registration, argv shapes, timeout 120 forwarding, OUTPUT_TAIL, and upstream-error conversion are unchanged. No autoMerge inspection, no session-state writes, no --auto-merge argument, no timeout work, no Phase102 assumptions. test_growth.py constructs UltrathinkContext() bare and stays compatible via the defaulted field. Existing eval case JSON files contain only ult_session_mark ultrathink cases and need no opt-in or migration; no blanket fixture enablement. Policy, roster, prompts, and assembled prompt already name the ship tools and stay byte-identical, so no prompt regeneration is required. External ultrathink-ship CLI behavior and live runtime are unverified planning evidence only; every test uses fakes and no real subprocess.
</context>
