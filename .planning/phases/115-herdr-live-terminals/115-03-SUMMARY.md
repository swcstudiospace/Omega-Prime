# Phase 115-03 Summary

## Implemented

- `events.py` (new) — the live typed-delta module (protocol defaults 9 and 10), stdlib + Starlette only:
  - `compute_deltas(previous, current)` — pure diff of successive served snapshots emitting exactly the five locked message shapes in the fixed order task_finished, task_changed, waiting_added, waiting_cleared, stale_changed, rows in snapshot order (previous order for waiting_cleared). Row identity is the served row `id`; rows keep the last entry per id and malformed entries are skipped. `task_finished` fires for every id newly present in `finished` (moved or appeared directly); `task_changed` is the upsert/new-active path plus rows whose non-stale fields changed; a stale-only transition emits `stale_changed` alone (a stale-only change never also emits `task_changed`, an active→finished move never emits `task_changed`); `None` previous treats every current row as new. No I/O, no logging, no state.
  - `EVENTS_WS_LIMIT = 16`, `EVENTS_WATCH_INTERVAL_S = 0.5`, and a private `_EMPTY_SNAPSHOT` literal that deliberately mirrors `app._empty_snapshot` (comment documents the mirror; events must not import app for the route factory).
  - `ConnectionLimiter` — synchronous counter with `try_acquire()`/`release()`, no semaphore semantics.
  - `make_events_ws_endpoint(poller, *, heartbeat_s=15.0, limit=EVENTS_WS_LIMIT, mono=time.monotonic)` — limiter check closes 4429 BEFORE accept; then accept, first message `{"type":"snapshot","snapshot":...}` (poller snapshot or the empty literal) framed with the SSE route's defensive serializer (`json.dumps(..., separators=(",", ":"), default=str)`). Writer/reader run concurrently with first-completion teardown; the reader discards every client frame and no token is ever read. The writer loops `poller.wait_for_update(heartbeat_s)` and re-reads and re-diffs `poller.snapshot()` on EVERY wake including timeouts (missed-wake recovery), adopting each new object as the diff base even when no deltas result; a heartbeat is sent whenever nothing has been sent for `heartbeat_s` on the injectable monotonic clock. The finally path releases the limiter exactly once and always ends with an explicit close frame (the 115-02 teardown lesson).
  - `TasksFileWatcher` — stat-polls `(st_mtime_ns, st_size)` at 0.5 s default with injectable `sleep`/`stat`, `None` signature for a missing file, fires `on_change()` exactly once per signature change (never on the baseline, never on unchanged stats), degrades every `OSError` to the missing-file signature instead of raising, logs nothing, and propagates cancellation. `path` is public for the CLI wiring test.
- `poller.py` — public `DashboardPoller.nudge(source)`: when a spec carries that source, `_next_due[source] = 0.0` so the next `run_forever` tick schedules it through the existing running-lock and interval rescheduling; unknown sources are a silent no-op; one docstring line, no logging. `normalize_tasks`' signature and call kwargs are untouched.
- `app.py` — keyword-only `tasks_path`/`tasks_watcher` (both default `None`; poller stays positional); the events module is imported inside `create_app`, the endpoint is built once with the existing `heartbeat_s`, and `WebSocketRoute("/ws/events", ...)` sits beside 115-02's terminal websocket route. No guard, CSP, `/api/snapshot`, or `/api/stream` change. The resolved watcher is exposed as `app.state.tasks_watcher`; the lifespan starts its `run()` task after `poller.start()` and cancels-and-awaits it before `poller.stop()` (CancelledError suppressed).
- `__main__.py` — the serve path passes its already-built `tasks_path` into `create_app`; subcommands, `--once`, `--stop`, the pidfile lifecycle and the loopback refusal are untouched.
- `test_dashboard_events_ws.py` (new) — 23 tests: pure delta cases (identical snapshots, note-only change, all stale transitions, combined note+stale ordering, upserts, active→finished, finished-only appearance, waiting add/clear, waiting→finished ordering, full ordered multi-change list, `None` previous, malformed rows) plus route tests through `create_app`/TestClient with explicit `host`/`origin` headers on 127.0.0.1:7441 only: snapshot-first with the locked seven keys, a4's task_finished within 2 s of a tasks.json rewrite (elapsed asserted < 2.0 s), waiting_added, heartbeat + stale_changed + the no-churn guard on a bare poller, 4403 refusals for foreign/missing Origin and bad Host with a localhost-origin success, the 16-connection cap with 4429 for the 17th and slot release after close, nudge scheduling with a 30 s-interval collector, the scripted-stat watcher unit (three fires: change, disappearance, reappearance), the discriminating wake test (30 s collector interval + 0.05 s watcher lands the delta < 2 s, so only watcher→nudge can deliver), lifespan cleanup (watcher cancellation observed through an instrumented sleep), `main()` threading `tasks_path` into `create_app`, and the no-watcher negative. No test binds a port, sleeps beyond injected intervals, touches the network, or mentions 7421.
