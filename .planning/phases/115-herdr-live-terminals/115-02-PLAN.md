## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser page to terminal websocket | Client-controlled frames (auth, input, keys) cross into a server that can type into a shell on the host; untrusted Origin/Host/token must never reach Herdr I/O. |
| WebSocket handshake headers to _DashboardGuards | Browsers do not apply CORS to websockets; Host and Origin are the only cross-site hijacking barriers before application logic runs. |
| Same-origin loopback page to GET /api/session | The attach token is the write-path credential; it must leave the process only for same-origin loopback GETs and never via logs, storage or cookies. |
| Dashboard process to host Herdr CLI | Forwarded keystrokes become argv to herdr send-text/send-keys (no shell); argv payloads may contain secrets typed by the operator and must never be logged. |
| Herdr pane output to client frames | Raw ANSI visible-screen text may contain tokens echoed by processes; frames cross back to the browser and must be redacted while staying renderable. |
