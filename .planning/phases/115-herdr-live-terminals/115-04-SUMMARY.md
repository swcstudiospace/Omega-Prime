# Phase 115-04 Summary

## Implemented

- `types.ts` — `Task` gains the optional `stale?: { reason: string; since: string } | null` field beside `herdr_pane` (protocol default 1); no other type changed.
- `useDashboard.ts` — additive websocket tier above the untouched SSE + poll chain inside the same `refreshKey` effect:
  - `parseMessage(raw)` validates the /ws/events discriminant and identity fields at the boundary and asserts the named message type; anything unparseable or unknown is null. `applyDelta(current, message)` applies task_changed (upsert by id), task_finished (remove from active and idle_sessions, upsert into finished), waiting_added (guarded append), waiting_cleared (filter) and stale_changed (writes the stale value, including null, onto the matching task across active and idle_sessions) immutably, returning null when a delta cannot be applied. Heartbeats are ignored entirely.
  - `connectWs()` builds the socket from `location.protocol`/`location.host` (`ws://…/ws/events`, wss on https). Snapshot messages are handled exactly like the SSE snapshot event; every applied delta updates `receivedAt`; an unknown, unparseable or inapplicable message triggers a single `void fetchSnapshot()`. `onopen` sets live, stops polling, closes any EventSource and resets the failure counter and backoff base; `onclose`/`onerror` (de-duplicated per socket) count one consecutive failure — below three, a full-jitter reconnect of `Math.random() × min(30 s, 1 s × 2^(failures−1))`; at three, the existing SSE `connect()` runs with polling underneath and a 30 s websocket retry re-enters `connectWs`, where a later successful open closes the EventSource and resets everything. `typeof WebSocket === 'undefined'` falls straight through to SSE. Teardown closes the socket and clears all timers beside the existing cleanup; every callback respects the disposed flag.
- `TerminalPanel.tsx` — two-view panel behind the unchanged `TerminalPanel` wrapper and its `key={taskId}` remount:
  - Session: `GET /api/session` on mount gives `{token, readonly}`; the token lives only in a ref used for the first websocket message — never rendered, logged, stored, or put in a URL. A failed or non-ok session fetch renders the SSE fallback directly.
  - Interactive view (session ok, WebSocket available, attached, socket healthy): `TerminalSurface` creates the bundled xterm `Terminal` (exact-pinned `@xterm/xterm@5.5.0`, registry-confirmed; `convertEol`, 24×80, no addons, css imported from the package — no CDN) once per interactive mount, opens it into the panel, disposes on unmount. The socket url is `${ws|wss}://${location.host}/ws/tasks/${encodeURIComponent(taskId)}/terminal`; on open the first message is exactly `{"type":"auth","token","mode"}` with mode `ro` when the session reported readonly or the read-only toggle is on, else `rw`. `{"type":"frame"}` payloads render as full screens (`terminal.reset()` then `terminal.write`) and refresh the last-updated stamp; `{"type":"status"}` maps to the badge, with `pane_closed` closing the socket and never auto-retrying. xterm `onData` forwards the exact-match named-key table (`\r`→enter, `\t`→tab, arrows, `\x1b`→escape, `\x7f`→backspace) as `{"type":"keys","keys":[name]}` and everything else as `{"type":"input","text"}` — only while the socket is open and the effective mode is rw. Controls: Attach/Detach button (detach closes and shows Detached; attach builds a fresh socket), read-only toggle (`aria-pressed`) that stops input sends immediately, and the badge (live/attached/detached/read-only/pane_closed/unavailable/no_session).
  - Fallback view: the legacy EventSource markup, url, statuses, actions and the `Read only · redacted · last 200 lines` subtitle are byte-identical, rendered on session-fetch failure, missing WebSocket or socket failure; a socket failure schedules a 30 s websocket retry that switches back when it connects. The optional `note` prop renders "No session attached — last note: {note}" beside the interactive no_session status and is appended to the fallback no_session paragraph.
- `TaskDetail.tsx` — the section heading shows the same STALE badge (reason visible, `since` in the title) for tasks with non-null stale, and the TerminalPanel mount passes `note={task ? item.detail ?? null : null}`.
- `Tasks.tsx` — task rows and idle-session rows render the guarded `stale-pill` badge (`STALE · {reason}`, since in the title) beside the state pill; nothing renders for fresh rows.
- `styles.css` — one self-contained `.stale-pill` rule (state-pill geometry, warning tint) beside the state-pill rules; no other css change.
