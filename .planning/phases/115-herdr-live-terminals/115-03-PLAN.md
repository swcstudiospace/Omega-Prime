<assumption_delta_decision>
- Decision: deltas are computed by diffing the full served snapshots (poller.snapshot() output), not from collector events — exactly what the locked LIVE_EVENTS wording specifies. Row identity is the snapshot row "id" (for tasks.json rows the model already derives "tasks:"-prefixed identities at model.py:663 and :693, so tests seed ids containing a colon to keep identities stable).
- Decision: task_finished fires for any id newly present in the finished bucket, not only ids previously seen in active — a tasks.json row written straight to done/failed and the active→finished move are the same user-visible event, and both are the "active/waiting row moving to finished or state done/failed" detection the mission names.
- Decision: stale_changed is a distinct message carved out of the row diff (stale lives inside task rows per 115-01 protocol default 1); a stale-only transition does not also emit a generic task_changed, so the frontend can treat task_changed as a row upsert and stale_changed as a badge update independently.
- Decision: the wake path is poller-side scheduling, not collector-side: nudge(source) only resets _next_due[source] to 0.0 and lets run_forever's existing tick loop (poller.py:89-102) do the scheduling, so the change respects the running-lock, interval rescheduling and _maybe_build pipeline without a second scheduling system.
- Decision: the stat watcher lives in events.py (per protocol default 10), is constructed by create_app when tasks_path is given, and is started/cancelled by the app lifespan beside poller.start()/stop(); __main__.py only passes tasks_path — no watcher logic in the CLI.
- No add-alongside debt: no frontend backoff/fallback (115-04), no terminal work (115-02), no heartbeat/stale/reconcile semantics (115-01) is part of this plan.
</assumption_delta_decision>
