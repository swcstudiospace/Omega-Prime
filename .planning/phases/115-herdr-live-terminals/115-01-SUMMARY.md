# Phase 115-01 Summary

## Implemented

- `status_file.py` — task rows now validate three optional liveness fields per protocol default 2: `last_heartbeat_at` (parseable ISO-8601 string, "Z" tolerated), `pid` (positive int, bool rejected), and `stale` (dict with exactly `{reason, since}`, `since` parseable ISO). Each has a dedicated helper (`_optional_iso`, `_optional_pid`, `_optional_stale`) raising `ValueError` with a prefixed field path; junk of every listed variant is rejected, all pre-existing validation and redaction behavior is unchanged, and the fields round-trip through `locked_tasks` + `_write_locked` like the established optional-key convention (absent keys emit as `None`).
- `status_file.heartbeat(path, task_id, *, state=None, note=None, pid=None, now=None)` — the single locked write path for liveness evidence: locates the row by exact id, sets `last_heartbeat_at` (injectable clock), overwrites only the optional fields that are not `None`, drops any persisted `stale` marker from the row, refreshes root `updated_at` with the same stamp, and returns a row copy. Unknown ids raise `ValueError` and write nothing; junk state values fail inside `_write_locked` re-validation; nothing is logged.
- `stale.py` (new, stdlib-only) — `DEFAULT_STALE_MINUTES = 20.0`, `REASONS = ("pid_dead", "pane_gone", "pane_exited", "no_heartbeat")`. `StaleChecker` takes injectable `clock`, `/proc`-backed `pid_alive`, defensively-normalizing `pane_lister` (list payloads, or dicts carrying a list under `panes`/`result`/`items`; returns `None` — unavailable, never an empty map — on subprocess/parse failure), and `stale_minutes`. `stale_reason`/`stale_map` evaluate working/blocked rows in fixed precedence (pid_dead > pane_gone > pane_exited > no_heartbeat) with the inclusive `>= N` boundary, lazy evidence checks (rows without pid/pane never trigger `/proc` walks or subprocesses), lister-`None` suppression of both pane reasons, and a stable `since` anchor: the row's newest liveness reference timestamp (`last_signal`), never the current time, so unchanged evidence is byte-identical across rebuilds. `normalize_pane_list` and `no_heartbeat` are exported for reuse.
- `model.py` — `Task` gains `stale: dict[str, str] | None = None` emitted from `to_dict`; `normalize_tasks`' signature and call kwargs are untouched.
- `poller.py` — `DashboardPoller` accepts keyword-only `stale_checker=None` and constructs the default `StaleChecker()` when omitted, so production snapshots carry staleness with no `__main__.py` edit. `_build_snapshot` applies `stale_map` poller-side, immediately after `normalize_tasks` and before numbering; `number_snapshot`'s in-place row mutation preserves the field. Checker exceptions flow into the existing normalization-error degradation path.
- `reconcile.py` (new) — `python3 -m omega_prime.dashboard.reconcile [--tasks PATH] [--apply] [--force] [--stale-minutes N]`, dry-run by default. Herdr is reached only through the injectable runner (`herdr pane list`, `herdr pane process-info --pane <id>` with pane ids gated by `_PANE_ID` before argv); runner failure degrades to an `unavailable` report with no fabricated pane deaths and pid-only checks still running. `--apply` attaches orphan panes matched by `herdr_launch.workspace_label` (lowest pane id per row, first row in file order wins) and stamps stale markers `{reason, since}` (row reference timestamp, run clock as fallback) only through `locked_tasks` + `_write_locked`; rows are never deleted and state/title/owner never change. A root `updated_at` younger than 15 minutes blocks row mutations unless `--force` (the report's `protected` flag reflects the effective state for the run). Dry-run prints a `redact_value`-passed JSON report of dead rows, no-heartbeat rows, attach candidates, Herdr availability, threshold, and protection state; invalid files print a redacted JSON error to stderr and exit 1.
