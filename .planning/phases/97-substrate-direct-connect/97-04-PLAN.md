<objective>
Implement the safe settings/configuration seam and honest diagnostics for substrate connection. Keep settings trust validation, environment precedence, URL/auth safety, startup propagation, and user-facing readiness behavior as one serialized unit because these paths share runtime construction and diagnostics. This plan owns the listed files exclusively; it does not own docs (97-05), tool argument changes (97-03), or transport changes (97-02). </objective>

<assumption_delta_decision>
- Settings path defaults to `~/.omega-prime/settings.json`; only `OMEGA_PRIME_SETTINGS_FILE` changes the path.
- The settings loader accepts explicit `process_env` plus injected home/path inputs for deterministic tests and returns a frozen `SettingsResult(effective_env, status, loaded_names, rejected_names, reasons)`; it never mutates `os.environ`.
- Process environment takes precedence by key presence, including an explicitly set empty string.
- The allowlist is exactly `SUBSTRATE_URL`, `HINDSIGHT_URL`, `ULTRATHINK_ROOT`, `ULTRATHINK_SHIP`, and `OMEGA_PRIME_STATE_DIR`, each string-valued. Credentials are never settings-file data. Secret-shaped keys (`TOKEN`, `KEY`, `SECRET`, `PASSWORD`, `PAT`, `AUTH`) are rejected by key name only; their values are never surfaced. Unknown non-secret keys are warned about and ignored.
- JSON parsing necessarily reads candidate bytes after safety checks have succeeded. A malformed document or any rejected unsafe/secret-shaped document is rejected atomically; startup continues with process environment only. Status/reasons survive explicit startup/runtime propagation without settings values.
- `load_runtime(env=mapping)` is pure for the new settings/substrate configuration seam: settings loading belongs at its caller. This does not change historical ambient configuration or redteam behavior elsewhere.
- `SUBSTRATE_URL` absent means not configured; `local` is the sole explicit local opt-in; otherwise require HTTPS and reject userinfo/credentials. Existing ready binding precedence and all blocking binding states remain intact.
- No live network check is required or permitted for doctor/setup. Fake servers are permitted only for isolated tests; no live configuration or settings file is changed.
</assumption_delta_decision>

<threat_model>
## Trust boundaries

| Boundary | Threat | Required mitigation |
|---|---|---|
| Settings path to JSON parser | Symlink/path traversal into repo, tracked data, or mutable files; TOCTOU replacement | Check lexical and resolved candidate ancestry against rev-parse worktree roots including linked worktrees; inspect tracked metadata; regular-file/permission and opened-file identity checks; fail closed before parsing if safety is uncertain |
| JSON key/value to configuration | Secret accidentally stored or arbitrary configuration injection | Exact five-key allowlist/string types; secret-shaped names refused by name only; unknown keys warned/ignored; malformed/rejected document atomic |
| Settings and process env to runtime | Ambient config leaks into explicit runtime; empty env mistaken for absent; provenance lost in SSE | Presence-based precedence; caller-owned explicit merge and separate status object; no `os.environ` mutation or downstream settings reread |
| URL/auth to transport and diagnostics | Localhost surprise, credential-bearing URL, token leakage through errors/chains | No implicit default, literal local opt-in, HTTPS and userinfo checks, safe URL text, preserve auth order and redact causes |
| Runtime to doctor/setup | Configuration mistaken for reachability; hidden degradation or fallback | Carry safe provenance to actual lead doctor and setup; no network probe; actionable FAIL and typed errors; blocked bindings remain blocked |

| T-W97-04-02 | Information disclosure | High | Mitigate | Refuse secret names without surfacing values; redact token and exception causes; never show credential URLs |
| T-W97-04-03 | Spoofing / unintended endpoint | High | Mitigate | Explicit URL, HTTPS validation, local opt-in only, saved binding precedence and blocking-state preservation |
| T-W97-04-04 | Misleading health status | Medium | Mitigate | Separate configured status from reachability; no network in doctor/setup; visible missing/degraded status |
