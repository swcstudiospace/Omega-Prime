## Task 1 — Rubric schema + scored cases + runner `--rubric` (EVAL-01)

Bounded files:

- `omega_prime/evals/rubric.py` (new)
- `omega_prime/evals/cases/rubric_cases.json` (new)
- `omega_prime/evals/runner.py` (additive only)
- `omega_prime/tests/test_evals_rubric.py` (new — executor MUST write)

Ordered actions:

1. Implement `omega_prime/evals/rubric.py`: rubric case schema
   `{case_id, turns, criteria: [{id, weight, check}]}`, loader + validator, and
   the deterministic predicate set over the transcript (`final contains/omits`,
   `tool-call shape`). Named errors for: missing/empty `case_id`, unknown
   predicate id, weights not summing to 1 (tolerance 1e-9), empty criteria.
   Total case score in [0,1] = weighted criterion scores. `judge`-kind criteria
   score via the judge module interface from Task 3 (import lazily so Task 1
   alone never imports network-capable modules); when the judge is disabled they
   record `judge: skipped` and contribute 0 with `judge_unavailable` unset.
2. Author `omega_prime/evals/cases/rubric_cases.json`: first set derived from the
   `redteam.json` scenario surface (same classes, scored instead of binary),
   every criterion `judge: none` initially. Each case carries `min_score`; the
   runner invocation fails (nonzero exit) when any case scores below its
   `min_score` (the nightly's pass signal, never the CI gate's).
3. Integrate `runner.py` additively: add `--rubric <file>` and `--output <file>`
   flags emitting per-case `{case_id, score, criteria, min_score}` records under
   a `rubric_cases` key. `run_suite` for `golden.json` + `redteam.json` and every
   existing report shape stays byte-identical when `--rubric` is absent.
   Do NOT change `run_case`/`_check` semantics for deterministic cases.
4. Write `omega_prime/tests/test_evals_rubric.py`: valid case loads and scores;
   unknown predicate / weights != 1 / missing `case_id` each raise the named
   error; runner `--rubric` emits `score` for every case; existing
   `test_evals.py` expectations still hold (do not edit `test_evals.py`).

PARENT-RUN verify (offline, parent runs after executors land):

```sh

python3 -m omega_prime.evals.runner --rubric omega_prime/evals/cases/rubric_cases.json --output /tmp/phase84-rubric.json && python3 -c "import json;d=json.load(open('/tmp/phase84-rubric.json'));assert all('score' in c for c in d['rubric_cases']),d"
python3 - <<'EOF'
import json
red = json.load(open('omega_prime/evals/cases/redteam.json'))
rub = json.load(open('omega_prime/evals/cases/rubric_cases.json'))
cases = rub if isinstance(rub, list) else rub.get('cases', rub.get('rubric_cases'))
def covers(rc, r):
    rid = r['id']
    stem = rid[len('redteam-'):] if rid.startswith('redteam-') else rid

assert not missing, f"rubric cases missing redteam classes: {missing}"
print(f"redteam coverage OK: {len(red)} classes covered by {len(cases)} rubric cases")
EOF
```

## Task 2 — History store + trend/regression check (EVAL-01, EVAL-02)

Bounded files:

- `omega_prime/evals/history.py` (new)
- `omega_prime/evals/trend.py` (new)
- `omega_prime/config.py` (`evals` node only: `regress_threshold`)
- `omega_prime/tests/test_evals_history.py` (new — executor MUST write)

Ordered actions:

1. Implement `omega_prime/evals/history.py`: append-only NDJSON store at
   `.omega-evals/history.ndjson` (repo root runtime data, not planning data).
   One JSON object per line per run per case:
   `{run_id, commit, case_id, score, criteria, timestamp}` where
   `run_id = <commit>-<utc-timestamp>`. Append creates parent dirs; read applies
   torn-tail repair exactly like the EventStore pattern (`tools/lead.py:359`):
   a truncated last line is dropped with a stderr warning, earlier lines intact.
   History writes are dark (nothing gates on them).
2. Implement `omega_prime/evals/trend.py` with CLI
   `python3 -m omega_prime.evals.trend --history <file> [--threshold X]`:
   reads history sequentially, prints per-case trend (first/last/min/mean,
   delta vs previous run for the same case), and a regression line naming every
   case whose score dropped >= threshold between the last two runs. Exit 1 on
   regression (naming the case ids + deltas), exit 0 on flat/green history.
   nonzero fail-closed with the offending line identified. Also support the
   committed-baseline mode mirroring `scripts/nightly_readiness_check.py`:
   `trend.py check --baseline omega_prime/evals/history-baseline.json --report
   <rubric-report>` exits 1 naming every case scoring below its baseline by >=
   threshold (or below `min_score`), and `trend.py --bless --report <report>
   --baseline <file>` rewrites the baseline (blessed only via reviewed PR —
   same contract as the readiness `--bless` flow).
3. Add the `evals` config node in `omega_prime/config.py` following the existing
   `_defaults` + `_env_overrides` style: `evals.regress_threshold` default `0.1`
   with env override `OMEGA_PRIME_EVALS_REGRESS_THRESHOLD` (invalid values fall
   back to the default loudly, never crash, never silently gate). `trend.py`
   reads the threshold from config unless `--threshold` is passed.
   Add `.omega-evals/` to `.gitignore` (history is runtime data, never committed).
4. Write `omega_prime/tests/test_evals_history.py`: append -> read round-trip
   preserves run-id + timestamp ordering; a hand-truncated last line is dropped
   with earlier lines intact; `trend` on a seeded two-run history with a
   synthetic drop >= threshold reports the regressed case and would exit 1
   (assert via the `compare`-level function, not via subprocess); flat history
   reports stable.

## Task 3 — Flag-gated judge + nightly workflow + gate invariant (EVAL-02)

Bounded files:

- `omega_prime/evals/judge.py` (new)
- `omega_prime/config.py` (`evals.judge` node only: `enabled`, `model`)
- `omega_prime/tests/test_evals_judge.py` (new — executor MUST write)
- `.github/workflows/nightly-evals.yml` (new)
- `omega_prime/evals/history-baseline.json` (new, committed — the cross-run
  comparison baseline; seeded from the initial rubric run, updated only via
  the Task 2 `--bless` command in a reviewed PR)

Ordered actions:

1. Implement `omega_prime/evals/judge.py`: `score_criterion(criterion,
   transcript, config)` behind the explicit flag. Module top level imports
   stdlib-only; every socket-capable import (`socket`, `ssl`, `http.client`,
   `urllib.request`, third-party clients) happens INSIDE the enabled-only code
   path, after the flag + model + credential checks pass. Rules: flag off (or
   model empty, or credential absent) => criterion records `judge: skipped`,
   zero network attempted; endpoint down => criterion scores 0 with
   `judge_unavailable: true`, suite still completes (recorded, never fabricated,
   never blocks). Rationale + model id stored per record; judge-scored criteria
   kept separable from deterministic ones in the record shape.
2. Add the `evals.judge` config node in `omega_prime/config.py` per plan-06
   rollout contract: `evals.judge.enabled` default `false`,
   `evals.judge.model` default `""` (judge refuses to start when enabled but
   model empty), env overrides `OMEGA_PRIME_EVALS_JUDGE_ENABLED` /
   `OMEGA_PRIME_EVALS_JUDGE_MODEL` using the file's truthy convention
   (`1/true/yes/on`). The endpoint credential comes from the environment/secret
   store only — never from the config file. No key reads, no client construction
   unless enabled AND model non-empty AND credential present.
3. Write `omega_prime/tests/test_evals_judge.py` proving flag-off zero-network:
   with the flag unset, monkeypatch `socket.socket` (and `socket.create_connection`)
   to raise on any call, block `ssl`, `http.client`, `urllib.request` imports via
   an import hook asserting they are never imported on the judge-off path, run
   the rubric suite over a `judge`-kind criterion, and assert completion with
   `judge: skipped` records. Plus: flag-on with a stubbed endpoint stores score
   + rationale; endpoint-down records `judge_unavailable: true` and the suite
   still completes.
4. Add `.github/workflows/nightly-evals.yml` mirroring `nightly-readiness.yml`
   (cron nightly + `workflow_dispatch`, `contents: read` + `issues: write`):
   install -> run deterministic suite -> run rubric suite (`--output`
   rubric-report.json) -> append history (`run_id` + timestamp) -> `trend.py`
   check as the failing step -> compare-against-committed-baseline as a second
   failing step (`trend.py check --baseline
   omega_prime/evals/history-baseline.json --report rubric-report.json`,
   exactly the `nightly_readiness_check.py check --baseline ... --report ...`
   precedent; exits 1 on regression, so a red nightly fails even though the
   NDJSON history itself is gitignored runtime data) -> upload
   report/history artifact (always) -> tracking-issue open-or-comment on failure
   (secret-gated skip pattern per `kb-refresh.yml` when judge secrets absent:
   judge steps skip, deterministic + rubric still run) -> close tracking issue
   on green. Seed `omega_prime/evals/history-baseline.json` (committed) from
   the initial rubric run in this task. The workflow never touches `ci.yml`
   semantics and judges nothing in push/PR.
   NOTE — cross-run comparison choice (checker BLOCKER): option (b), committed
   baseline + bless-style update, mirroring the `readiness_baseline.json` +
   `--bless` precedent. Option (a) (restore prior nightly history artifact) is
   rejected: prior-run artifact restore needs a third-party download action and
   is unverifiable offline, while the committed baseline is reviewable in-PR
   and assertable in the parent-run shape check below.
5. Gate-invariant proof: do NOT edit `.github/workflows/ci.yml` in this task
   (any edit must be strictly additive and is a plan deviation to justify).
