# Phase 98 — Shared memory via substrate, Hindsight fallback

**Status:** Frozen design context. Implementation and local verification are recorded in `SUMMARY.md`; ordered phase-97 rebase/integration remains pending. The operator's parallel-mode decision supersedes the planning-time dependency gate for branch-local work.

**Requirement:** MEM-98-01 through MEM-98-10 (phase-local planning labels; not tracker IDs).

**Goal:** Provide source-aware shared memory across local storage, Substrate, and optional Hindsight. Recall always considers local memory, configured Substrate, and configured Hindsight independently. Retain persists locally first, then writes to every configured Substrate regardless of selector, and to Hindsight only when Hindsight is selected. Explicit configuration, scope, authorization, and remote failures must be visible and must not silently become local fallback or empty results.

## Requirements and success criteria

All requirements below remain unchecked until implementation and verification are completed.

- [ ] **MEM-98-01 — Selector and resolution.** `OMEGA_PRIME_MEMORY_BACKEND=local|substrate|hindsight`; default to substrate only when the authoritative phase-97 resolver supplies an explicitly configured/effective URL, otherwise local. Selector is a write preference, not a recall opt-out: configured substrate remains a recall and write participant under every selector. Invalid selectors/configuration fail safely; explicit missing remote selection reports configuration failure rather than silently falling back. No loopback-default probing to infer configuration.
- [ ] **MEM-98-02 — Merged recall and provenance.** Query local, resolved Substrate, and configured Hindsight independently for all selector values; hash canonical content, merge duplicate provenance, preserve IDs/banks/scope/repo and each source's original score without comparing unlike scores or fabricating scores. - [ ] **MEM-98-03 — Local-first stable-identity retain.** Validate before side effects; local save first; then publish to every configured Substrate regardless of selector, and report any non-accepted required Substrate write explicitly (`local_saved: true`, overall `ok: false`, sanitized error). Generate one UUID per logical operation and reuse its stable idempotency identity for transport retries and safely bound explicit caller retries. Never invent or guess phase-97 `expected_version` semantics. Do not claim exactly-once without server support.
- [ ] **MEM-98-04 — Selected-only Hindsight writes.** Configured Hindsight participates in recall regardless of selector. It receives writes only when selected explicitly as `hindsight`, after local persistence. Report its failure without swallowing it. Do not claim `document_id` is idempotent absent an authoritative service contract.
- [ ] **MEM-98-05 — Truthful per-backend states and outages.** Show all backend statuses, including `not_configured`; supported states are exactly `answered`, `empty`, `not_configured`, `unreachable`, and `unauthorized`. - [ ] **MEM-98-06 — Command and doctor reporting.** `/omega-recall`, `/omega-retain`, and the actual `LeadClient.doctor` path use the shared contract and report all three backend names and truthful states/participation; retain command failure reflects failure of any required configured remote publication, regardless of selector. - [ ] **MEM-98-07 — Security, scope, repo, and bounds.** Validate trusted scope/repo and content/query/limit/metadata bounds before IO; enforce repo isolation across every source, including local/global notes and shared Hindsight banks. Reject unsupported cross-repo results rather than trusting caller-supplied bank labels. Hindsight origin is HTTPS only; reject userinfo, query/fragment, and unsafe bank/path segments before credentials/network; obtain keys only through environment or mode-checked secret files via the existing broker; redact every key/error path, including broker/redaction failures. ## Frozen design contract for the four plans

This is a proposed phase contract, not a claim about the current checkout or phase 97. Rebase/re-read after phase 97 and confirm its signatures and error visibility before runtime work. If an upstream schema conflicts, stop before coding and resolve the contract; do not guess.

- `omega_prime/memory/backends.py` will expose `resolve_memory_backends(...) -> MemoryBackends`, with the local store, resolved substrate client, optional Hindsight service, trusted default scope/repo, selected backend, and safe configuration states. It owns resolution, types, validation/canonicalization helpers, not complete coordinator operations.
- `omega_prime/memory/recall.py` will expose `recall_memory(backends, query, *, scope, repo, limit, banks=None, include_shared=True) -> dict`.
- `omega_prime/memory/retain.py` will expose `retain_memory(backends, content, *, scope, repo, kind, operation_id=None, expected_version=None, source=None, receipt_path=None, tags=None, graph_id=None, task_id=None) -> dict`. `graph_id` and `task_id` are appended optional fields so existing positional/keyword API ordering remains intact; persist them as separate evidence metadata, never smuggle them into content or tags.
- Recall response shape: `{selected_backend, scope, repo, backends: {name: {state, attempted, error?}}, results: [{content, content_hash, sources: [{backend, bank?, id?, scope?, repo?, score?}]}]}`. Every configured/available source gets its own state before merge/dedup/truncation. Structured error diagnostics do not replace the exact state enum. Do not maintain a second legacy hit representation: readiness consumers migrate to this `results` list.
- Retain response shape: `{ok, local_saved, idempotency_key, selected_backend, backends, ...error?}`. Include all three backend names and distinguish write participation from configuration: `not_configured` means absent configuration only; a configured but unselected Hindsight backend is `attempted: false` / `participation: not_attempted`, not `not_configured`, and has no write-operation state. Only accepted Substrate status is success. An explicit caller operation ID is reusable only for identical canonical payload, scope/repo, and destination binding; reject mismatched reuse. Existing local exact-entry dedup remains; do not use a permanent content hash as the logical operation identity. No new retry loop, queue, or background worker.
- Canonical hash is SHA-256 of UTF-8 after stripping outer whitespace and normalizing CRLF/CR to LF. Do not case-fold or strip arbitrary bracketed content. Existing known local bank wrappers may be normalized only in the adapter. Deterministic source order: local, substrate, Hindsight; preserve source order within each backend. Apply global cap only after merge. Do not compare scores from unlike engines; preserve original source scores as supplied.
- Scope/repo is trusted context, not an arbitrary model authorization choice. Validate before any local or remote IO. Every backend must enforce/filter the same repo boundary; legacy records without repo provenance are not automatically repo-scoped. Keep old local banks readable in unscoped recall. Shared Hindsight bank is not inherently repo-isolated; require proven source filtering or a secure mapping before including scoped hits.
- Retain always writes local first; local persistence refusal suppresses all remote writes. Every configured substrate participates in retention regardless of selector, and any non-accepted required Substrate publication is an overall failure even when Hindsight is selected. Hindsight writes only for selected Hindsight. No rollback of local data after remote refusal. Preserve user profile and growth replace/remove as local-only; do not publish USER.md or seed onboarding records accidentally.
- **Local record codec (shared wave-1 contract):** `encode_local_record(record)->str` and `decode_local_record(stored_text, expected_bank)->LocalRecord|LegacyRecord` live in `memory/backends.py`. Encoding returns the complete stored string: exactly one `[hindsight:<bank>] [omega-memory:v1]` wrapper plus compact JSON serialized with `ensure_ascii=False, sort_keys=True, separators=(",",":")`. Retain passes that complete string directly to `MemoryStore.add("memory", encoded)` and never through `Hindsight.retain(encoded)`, which would double-wrap it. The JSON object fields are exactly `v=1, bank, scope, repo` (string or null), `kind`, `content`, `source` (string or null), `receipt_path` (string or null), `tags` (list of strings), `graph_id` (string or null), `task_id` (string or null). Decode consumes the complete stored string, strips and validates the exact known outer bank envelope internally, then parses the inner marker/JSON and matches its bank to the outer bank. Records from other banks are ineligible, not malformed. Marker-free legacy entries from the expected bank remain unscoped; a recognized malformed versioned record fails. Search decoded content, not metadata; hash only decoded canonical content. Newlines/quotes/backslashes are JSON-escaped; reject `ENTRY_DELIMITER` before encoding. Count complete wrapper, JSON, and existing separators against the existing 2200-character memory budget; do not increase it. Do not store operation UUID in the fact; preserve existing exact-entry local dedup.
- **Operation binding ledger:** `MemoryBackends` owns one in-memory binding ledger shared across both tool families. Generate one UUID per logical operation and bind it before local mutation. Fingerprint canonical typed JSON for the exact versioned record (content, scope/repo, kind/bank, evidence/tags/graph/task), phase-97 `expected_version`, selected backend, and normalized effective write-destination identity set without credentials. A known ID is reusable across separate caller invocations only with identical fingerprint; any mismatch refuses before local or network IO. Unknown caller-supplied IDs are refused before IO, including after restart/backend recreation or eviction; never adopt/reissue/mint a replacement for that supplied ID. Keep most recent 1024 completed bindings in LRU order; never evict in-flight entries. No TTL, session/time cap, journal, operation-count cap, retry loop, queue, or background worker. The returned key is not an exactly-once promise absent verified server support.
- Ordinary existing per-backend HTTP request timeouts remain allowed. A recall timeout is that source's `unreachable` result and must not suppress other hits; a required retain timeout reports `local_saved:true`, `ok:false`, sanitized diagnostics and still attempts other required destinations. Add no session, turn, or execution-budget time caps.
- `SubstrateClient.memory_write` phase-97 required signature/error/status contract, especially `expected_version` and idempotency support, is an execution prerequisite. `None` is not assumed to mean wildcard. HttpTransport POST retries make stable idempotency necessary before first send. Do not claim Hindsight `document_id` dedup semantics without a server contract.
- All three backend labels are present in recall and doctor status output, even if not configured. For write results, all three labels are present and `attempted`/`participation` distinguish an unselected configured backend from an absent backend; `not_configured` is reserved for absent configuration. Local-only with remote sources absent is a successful local operation; explicitly selected but missing remote is a configuration error. Synchronous service operations use existing `asyncio.to_thread` at async registration seams; do not invent async APIs.
