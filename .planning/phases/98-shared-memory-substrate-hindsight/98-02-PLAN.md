# Phase 98 Plan 02: source-aware recall and lead/readiness cutover

## Objective

Implement the complete deterministic recall merge and move every lead-tool/readiness caller from bank-grouped string entries to the single frozen source-aware result shape. The lead retain handler is wired to plan 03's exact API, but plan 03 owns the retain implementation and this plan does not implement duplicate write behavior. Production registry composition and lead doctor reporting belong exclusively to plan 04.

## Context

This is wave 2 and depends on plan 01. Do not begin until `omega_prime/memory/backends.py` and HindsightService's safe structured outcome/provenance contract are complete. Plan 03 is an independent wave-2 peer and owns `omega_prime/memory/retain.py` plus growth/provider. The two wave-2 units consume only the frozen shared contract in the phase `PLAN.md`; neither edits shared backend primitives or the other's files. There must be no runtime import of an unproduced peer type before both wave-2 implementations are ready for union integration. During implementation, keep handlers usable through explicit injected dependencies; preserve existing local-only operation until plan-04 composition installs the coordinator. Validate all memory scope/repo inputs before any local or remote I/O.

The frozen API and result contract (also used by plan 03) is:

```python
resolve_memory_backends(...) -> MemoryBackends
recall_memory(backends, query, *, scope, repo, limit, banks=None, include_shared=True) -> dict
retain_memory(backends, content, *, scope, repo, kind, operation_id=None,
              expected_version=None, source=None, receipt_path=None, tags=None,
              graph_id=None, task_id=None) -> dict
```
Plan 01 defines the backend/result types and canonicalization. Plan 03 implements the final function above. Plan 04 composes a shared `MemoryBackends` and reports doctor state. These synchronous operations use the existing `asyncio.to_thread` pattern at async registration seams; do not introduce an async backend API or new concurrency framework.

Recall returns one envelope:

```python
{
  "selected_backend": "local|substrate|hindsight",
  "scope": "validated scope", "repo": "validated repo or null",
  "backends": {
    "local": {"state": "answered|empty|not_configured|unreachable|unauthorized", "error": "sanitized optional diagnostic"},
    "substrate": {"state": "...", "error": "sanitized optional diagnostic"},
    "hindsight": {"state": "...", "error": "sanitized optional diagnostic"}
  },
  "results": [{"content": "...", "content_hash": "sha256:...",
                "sources": [{"backend": "...", "bank": "...", "id": "...",
                             "scope": "...", "repo": "...", "score": "original backend score"}]}]
}
```

No second `results[*].entries` or legacy `banks` data tree is emitted. States are determined per backend before deduplication and global limit. Sources are ordered local, substrate, Hindsight; preserve each backend's returned order. Hash canonicalization is SHA-256 of UTF-8 `(content.strip().replace("\r\n", "\n").replace("\r", "\n"))`, without case folding or fuzzy matching. The local codec consumes the complete stored string and validates/strips only its exact known outer bank envelope internally; search and hash only decoded content. Merge provenance for matching hashes and preserve backend scores as opaque per-source values—never compare or synthesize a cross-backend score. Apply one documented global limit after merging.

Repo isolation is mandatory across all three sources. Validate trusted scope and repo before any operation. In repo-scoped recall, include only entries with explicit matching repo provenance; do not infer repository ownership for global local notes or shared Hindsight-bank entries. Legacy canonical/alias local banks remain readable in unscoped recall. `include_shared` and bank selection may narrow eligible reads but cannot override repo isolation or make a caller-supplied bank an authorization boundary.

### Task 1: Implement complete independent recall fanout and normalization

**Files:** `omega_prime/memory/recall.py`, `omega_prime/tests/test_memory_recall.py`

**Action:** Implement the full `recall_memory(backends, query, *, scope, repo, limit, banks=None, include_shared=True)` API using plan-01 types and public phase-97 substrate/Hindsight APIs. For each backend, determine whether it participates from safe configuration, issue independent source reads, and map typed outcomes to exactly the frozen state vocabulary. Never suppress other reads because one fails or because local storage is absent. Do not turn exceptions or malformed envelopes into empty success. Preserve local canonical and legacy bank reads in unscoped mode. Filter every source's records by validated scope/repo provenance before returning repo-scoped hits. Normalize to content, canonical hash, and source metadata; merge equal hashes while retaining each contributing backend, bank, ID, scope, repo, and unmodified score. Preserve deterministic source ordering and source-native row ordering. Set source state based on the valid per-source response before deduplication/truncation. Apply the global result limit only after deterministic aggregation.

**Verify:** Add fake-source tests for the complete state matrix (answered, empty, not_configured, unreachable, unauthorized) independently for each backend; one or two failed sources alongside successful ones; missing local store with working remote source; malformed payloads not empty; configured Hindsight recall even when selector is local/substrate; hash merge across all three sources with all provenance; distinct content retained; stable order and global cap; states remain accurate when duplicates/truncation occur; scores are preserved but not ranked/compared; repo isolation against global local notes, wrong-repo remote entries, and shared Hindsight records without repo provenance; unscoped legacy alias reads; validation failures make zero fake calls.

**Done:** Recall is a complete working implementation, not a scaffold; every backend's source state and all normalized hits are truthful under partial failure and isolation.

Before every local search, reload the authoritative persisted store using the existing `load_from_disk` convention; never use an instance's stale construction-time snapshot. Decode complete stored values through the plan-01 codec, which validates/strips exactly the expected bank envelope internally; a different bank is ineligible, not malformed, and expected-bank legacy values without a version marker remain plain unscoped content. Query/search only decoded content, never serialized metadata. A read/reload failure is that backend's sanitized failure state, not a healthy empty result, while independently configured remote reads still proceed. Tests must prove that a second `MemoryStore` instance's write is visible to the already-constructed recall instance on the next search, and that retain→reload→same-repo recall preserves content and identical canonical hashes across local, substrate, and Hindsight records.

Network timeout acceptance uses ordinary per-request timeouts only: a timed-out backend is `unreachable`, successful sources' hits remain, and all configured sources are still attempted. Add fake-timeout recall coverage through the real operation; no session, turn, execution-budget, or wall-clock cap.
