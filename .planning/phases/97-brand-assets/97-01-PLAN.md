<decisions_applied>
- Method for seven sizes (planner decision): add `--size N` and `--out PATH` to `omega_prime/scripts/render_raster.py` and pass them to CairoSVG as `--output-width N --output-height N`. Rejected: one SVG wrapper per size. A wrapper is a different SVG, so `render_raster.py` would stamp the wrapper's digest, not the `assets/icon.svg` digest that the success criteria require, and the wrapper would need its own source copy. Rejected: a second output sibling per size without `--out`, because the icons live in `icons/`, not beside the SVG.
- The single source digest is the SHA-256 of `assets/icon.svg`. It is recorded in every icon PNG by `render_raster.py`. No new digest file is created.
- CairoSVG is invoked from PATH as `cairosvg`. `cairosvg --help` lists `--output-width` and `--output-height`. If `cairosvg` is missing from PATH, STOP and report `render_raster: cairosvg is not on PATH`; do not write a placeholder PNG or hand-stamp bytes.
- Tracer-first: the path is one existing pipeline (`render_raster.py` -> `cairosvg` -> PNG -> digest test). The only unknown, whether this cairosvg accepts `--output-width` and `--output-height`, was checked against `cairosvg --help` during planning. Task 1 wires the option; Task 2 runs it end-to-end for all seven sizes and checks the result on disk, so no separate tracer task is needed.
- Commit scope: commit only the paths listed in `files_modified`. Never stage `.planning/` (commit_docs is false), `uv.lock` or the pre-existing modified `.planning/*` files.
</decisions_applied>
